# 右键功能分区草稿

- **状态：** 当前覆盖范围已完成全局审查并按 CA0、CM1、CM2、CM3、CM4 分步实现和本地验收
- **更新日期：** 2026-09-19
- **当前覆盖：** 编辑器与 Diff 行号栏/代码行 Git Blame；Files 文件与文件夹条目；Changes 变更文件条目；Branches 分支条目；History 单条与连续多选提交记录；提交详情变更文件夹与文件

## 文档目的

本文按功能区逐步收集右键菜单的产品行为。2026-09-15 已对当前覆盖范围统一审查菜单基础设施、状态归属、桌面适配、文件操作能力和实施顺序。

本文主要回答“用户在某个功能区右键时应该看到什么、动作如何表现、哪些状态必须安全处理”，不代表其中缺失的后端能力已经存在。统一架构采用“共享窗口菜单宿主、功能区拥有目标和动作、应用/领域服务拥有执行”的组合方式，详见 [`ADR-0013`](../architecture/decisions/0013-feature-owned-context-actions.md) 和 [`实施计划`](../engineering/context-action-system.md)。

Android Studio 截图只作为桌面菜单密度、分组和二级菜单交互的参考。Asterlyn 不继承截图中未列入本草稿的能力、资产、图标、快捷键或产品结构。

## 全局审查结论

- 同一窗口只建立一个共享的菜单展示宿主，统一定位、焦点、键盘、二级菜单、无障碍、窗口生命周期和样式；它不读取或修改任何业务状态。
- 每个功能区独立拥有右键目标、选择关系、菜单内容、可用性解释和动作路由。共享宿主不能把 Files、Changes、Branches 或 History 的选择合并成一个全局状态。
- 不建立集中收纳所有动作的大型 switch/注册表。菜单动作回到创建该菜单的功能区，并复用工具栏、普通点击、键盘或现有审查流程所调用的同一应用动作。
- 打开菜单必须同步完成且不调用 Git、文件系统、网络或 Tauri 命令。目录扫描、拓扑分析和写操作计划等昂贵预检在用户激活动作后进入具名加载/审查界面。
- 第一版使用 WebView 内的自定义业务菜单；在文件管理器中显示和系统回收站仍通过经过授权的平台适配器完成。现有项目、History 筛选、编辑器标签和 Push 模式下拉菜单不因本设计被强行合并。
- Asterlyn 内部文件操作剪贴板第一版限定当前窗口和当前工作区世代，只保存精确身份而不缓存文件字节；项目切换或源身份变化会使其失效，不与系统文件剪贴板互通。
- 同名粘贴第一版只允许输入新名称或取消，不提供静默覆盖。菜单最多一层二级菜单，不持久化打开状态。
- 当前未定义 Changes 分组/目录、Tag、远程分组、仓库根容器、编辑器标签、除 E1 行号栏外的 Diff 内容、终端内容和空白区域的业务右键菜单；共享系统为它们保留扩展位置，但实现不能自行发明功能项。
- 现有架构无需推倒重写。实现前需要补齐共享菜单宿主、类型化跨功能导航、文本剪贴板/桌面路径适配，以及 R5 工作区文件操作基础；分支、范围 Diff、历史 blob 等缺口继续作为独立 Git/应用能力建设，不能写进菜单层。

## 草稿 E1：编辑器行号栏/代码行 Git Blame annotations

### 定位与范围

这个功能已经存在，并已作为统一右键管理系统的首个迁移样本完成 CA0，而不是重新开发的
Git 能力。用户在普通文本编辑器、并排工作区 Diff 或并排提交 Diff 的行号栏或代码行上右键，可以按需显示或隐藏该文档版本的 Git Blame 行来源。

- 右键命中普通行号栏、代码行或已显示的 Blame 标注栏时打开同一个菜单；菜单作用于整个文档或整个 Diff 侧，不作用于命中的单行、提交或变更块。
- 打开菜单不移动文本光标、选择范围、Diff 当前变更或编辑器标签选择，也不触发 Git 请求。
- 普通编辑器只有一个目标；并排 Diff 的旧侧和新侧是两个独立目标，可以分别加载、显示和隐藏。
- 统一 Diff 继续显示同一个可聚焦菜单项，但明确说明需要切换为并排 Diff；本次不尝试从统一行号反推旧侧或新侧。
- 图片 Diff、文件树和提交详情树不属于本菜单。代码行只是 E1 的另一个命中区域，编辑器正文不因此获得其他业务菜单项；每行 History、复制作者/提交 ID、跳转提交等能力也不随本次迁移新增。

### 菜单结构与状态

菜单保持一个 `menuitemcheckbox`，稳定动作身份为 `editor.git-blame.toggle`。第一轮迁移保留当前动态文案和行为，不把展示层重构混入产品改版：

| 状态 | 文案与表现 | 激活结果 |
| --- | --- | --- |
| 未显示且可用 | 使用 Git Blame 显示行来源；未勾选 | 关闭菜单并开始一次按需加载 |
| 正在加载 | 正在加载 Git Blame…；忙碌且不可重复启动 | 保持可聚焦并说明正在加载，不启动第二次请求 |
| 已显示 | 隐藏 Git Blame 行来源；已勾选 | 立即移除当前目标的标注和结果 |
| 当前不可用 | 未勾选并显示具体原因 | 不调用 Git；激活时读出或显示同一原因 |

菜单打开本身只读取已接受的前端状态。加载成功、部分结果、隐藏和失败继续使用现有统一反馈通道；只有状态栏文字不能替代菜单项的忙碌与不可用语义。

### 精确目标与版本映射

菜单会话捕获工作区世代、编辑器文档键、标签/挂载身份、文档加载世代、仓库根、`repositoryId`、安全仓库相对路径、Diff 侧，以及精确 `GitBlameSource`（`commitOid` 与 `parent`）。DOM 行、屏幕行号、短哈希和当前显示文案都不是动作身份。

| 表面 | 旧侧/普通目标 | 新侧 | 不可用边界 |
| --- | --- | --- | --- |
| 普通已保存文件 | 当前工作树中的已跟踪文件，`commitOid = null` | — | 非 Git、只读/未跟踪、未保存或正在保存时不可用 |
| 工作区并排 Diff | 当前 `HEAD` 上的原路径或当前路径 | 当前工作树上的当前路径 | 新增/未跟踪没有旧侧；删除没有新侧；未跟踪新侧不可用 |
| 提交并排 Diff | 精确提交第一父版本，重命名时使用原路径 | 精确提交版本，使用新路径 | 新增（包括根提交首次加入的文件）没有旧侧；删除没有新侧 |
| 任意统一 Diff | — | — | 不可用，并提示切换到并排 Diff |

执行显示动作时，编辑器层先确认菜单目标仍是同一文档、版本和 Diff 侧；Git 边界再验证仓库根、完整对象 ID、相对路径和父提交语义。结果返回后仍需通过请求世代、目标身份和来源一致性检查，过期结果直接丢弃，不能安装到后来复用的编辑器或另一侧。

### 显示、失效和生命周期

- 加载成功后按现有有界 hunk 结果安装标注，不展开成长期保留的逐行副本；被截断的完整记录可以显示，但必须给出“结果受限”反馈。
- 普通文件一旦编辑，立即清除旧标注并把动作变为“请先保存”；保存完成并获得新的权威内容版本后才重新可用，不自动重新加载。
- Diff 文档、路径、提交 OID、布局、侧来源或工作区变化时清除受影响结果和请求。切换为统一 Diff 不能保留一个看似仍绑定到某侧的菜单目标。
- 关闭菜单不会取消已经开始的 Git 读取；来源变化或隐藏动作通过请求世代使旧完成结果失效。若以后增加真实取消，必须由 Git Blame 能力定义，不能由菜单宿主假装已经取消。
- 窗口失焦、尺寸变化、编辑器释放、重新挂载、打开另一个业务菜单或目标失效时关闭菜单，并把焦点还给仍存在的编辑器；窗口之间不能共享活动菜单状态。

### 纳入统一架构的重构边界

现有实现中的模块级 `activeMenu`、直接向 `document.body` 创建 DOM、全局 document/window
监听和 `closeGutterMenu()` 调用全部迁出 CodeMirror gutter 模块：

- 每个原生窗口的 `ContextMenuHost` 负责菜单 DOM、定位、焦点、键盘、窗口事件和释放；不读取 Blame 或编辑器状态。
- Editor 功能拥有 `GitBlameSource`、普通/左右侧状态、请求世代、加载/结果和动作执行，并同步构造这个单项菜单模型。
- CodeMirror 行号栏和代码行事件只通过窄端口提交“锚点坐标 + 稳定编辑器目标”，不保存活动菜单，不直接访问其他功能区，也不把命中行当成 Blame 请求参数。
- 现有有界 `git blame --incremental --no-progress`、根解析、对象/路径验证、hunk 模型和懒加载边界保留；本次不重写已验证的 Git 核心。
- 中英文文案、主题或缩放变化由窗口宿主更新/关闭当前展示，不修改正在加载的业务请求；功能释放后不得残留监听器、菜单节点或可回调到旧编辑器的闭包。

### 验收草稿

1. 普通已保存跟踪文件可以显示和隐藏标注；编辑后标注立即失效，保存前给出可理解原因。
2. 工作区 Diff 的 `HEAD`/工作树和提交 Diff 的父提交/当前提交映射准确，左右侧状态互不覆盖；新增、删除、重命名、根提交和统一 Diff 具有正确的空侧或不可用行为。
3. 右键行号栏、代码行和 Blame 标注栏得到同一动作，打开菜单不改变光标、文本选择、Diff 选择或触发 Git。
4. 菜单在加载中不能重复请求；慢请求在文档、来源、布局、窗口或工作区变化后不能把结果装到过期目标。
5. 一个窗口打开新菜单只关闭该窗口旧菜单；多窗口没有模块级共享状态，释放后无 document/window 监听器和旧编辑器回调残留。
6. 菜单具有正确的 `menu`/`menuitemcheckbox`、勾选、忙碌、`aria-disabled`、原因说明、Escape、外部点击、边缘定位和焦点恢复行为。
7. 迁移前已有的有界输出、部分 hunk、懒加载和编辑/重挂载失效测试继续通过，并补充共享宿主的窗口隔离与键盘测试。
8. 前端检查、构建、适用 Git/Rust 测试、资源变化和已知平台限制写入新的接受证据。

## 草稿 F1：Files 文件与文件夹条目

### 目标

用户在 Files 树中的一个文件或文件夹上打开右键菜单后，可以完成围绕该条目最常用的文件系统和历史查看操作，而不需要进入一个大型 IDE 菜单。

文件和文件夹保持相同的菜单项与分组，差异只来自操作目标和当前状态。Files 空白区域、编辑器标签、Changes、History、Branches、Diff 正文和终端由各自草稿定义；E1 只覆盖编辑器/Diff 行号栏。工作区根不是普通树条目；若以后显示根条目，需要另行定义不可剪切、不可重命名和不可删除等保护规则。

### 打开和目标规则

- 鼠标右键命中文件或文件夹行时，Files 选中该条目并打开菜单，但不同时打开文件或切换文件夹展开状态。
- 键盘焦点位于文件或文件夹行时，`Shift+F10` 或系统菜单键在该行附近打开相同菜单。
- 菜单保存的是当前工作区世代下的稳定条目身份，包括条目种类、工作区根、`repositoryId`、仓库相对路径、工作区相对路径和只读属性；不能把虚拟列表中的 DOM 行或行号当成操作身份。
- 菜单打开不代表授权写入。每个读取或修改动作在执行时重新确认当前工作区、条目身份、源版本或目录清单、目标状态和写入权限。
- 条目在菜单打开后消失、工作区切换、列表滚动、窗口失焦或窗口尺寸变化时关闭菜单。状态变化只关闭或刷新菜单，不自动执行其他动作。
- 只有确认命中文件或文件夹行时才接管浏览器的 `contextmenu` 事件；本草稿不改变编辑器、终端或其他区域的现有右键行为。

### 菜单结构

菜单从上到下固定为以下分组。平台快捷键是否显示留到全局审查统一决定。

| 分组 | 菜单项 | 主要结果 |
| --- | --- | --- |
| 创建 | 新建文件… | 文件目标使用其父目录；文件夹目标使用文件夹内部 |
| 剪贴板 | 剪切 | 将目标文件或文件夹记录为待移动条目 |
| 剪贴板 | 复制 | 将目标文件或文件夹记录为待复制条目 |
| 剪贴板 | 粘贴 | 文件目标粘贴到其父目录；文件夹目标粘贴到文件夹内部 |
| 系统 | 在文件管理器中显示 | 在 Finder、文件资源管理器或 Linux 文件管理器中显示目标 |
| 文件 | 重命名… | 在 Files 树内编辑文件或文件夹的完整名称 |
| 文件 | 复制路径 › 文件名 | 复制文件名或文件夹名 |
| 文件 | 复制路径 › 相对路径 | 复制工作区根相对路径 |
| 文件 | 复制路径 › 绝对路径 | 复制当前平台格式的绝对路径 |
| Git | Git History | 打开仅包含该文件或文件夹路径的 Git History 查询 |
| 危险操作 | 删除… | 确认后将文件或文件夹移入系统回收站/废纸篓 |

分隔线位于“新建文件”之后、“粘贴”之后、“Git History”之前和“删除”之前。第一版只有“复制路径”需要二级菜单。

### 可用性

| 条目状态 | 创建/剪切/复制/粘贴/重命名/删除 | 复制路径/在文件管理器中显示 | Git History |
| --- | --- | --- | --- |
| Git 已跟踪或普通可写文件/文件夹 | 可用，仍需执行时复核 | 可用 | Git 路径含已跟踪内容时可用 |
| Git 未跟踪文件 | 可用，仍需执行时复核 | 可用 | 不可用：文件尚无历史 |
| 仅含未跟踪内容的文件夹 | 可用，仍需执行时复核 | 可用 | 不可用：该目录路径下尚无历史 |
| Git 忽略的只读预览文件/派生文件夹 | 不可用：只读身份不能进入文件修改能力 | 可用 | 不可用：忽略条目没有已授权的历史入口 |
| 普通非 Git 工作区文件/文件夹 | 可用，仍需执行时复核 | 可用 | 不可用：当前工作区没有 Git 能力 |
| 条目已消失或身份已过期 | 菜单关闭；动作若已开始则失败并触发定向重整 | 不再使用旧路径执行 | 不再使用旧身份执行 |
| 当前存在冲突、保存或其他互斥写入 | 保持可聚焦但语义不可用，并说明具体阻塞原因 | 只读动作仍可用 | 只读历史查询仍可用 |

不可用项使用可聚焦的语义不可用状态。激活后显示当前真实原因，不使用原生 `disabled` 静默吞掉操作。

### 文件夹递归操作的额外边界

当前 Files 文件夹主要由文件路径投影产生，不能把屏幕上可见的子项误认为完整目录内容。对文件夹执行剪切、复制、粘贴、重命名或删除前，后端必须重新取得该目录的授权身份并进行受限预检。

- 预检覆盖磁盘上的实际子树，而不是只覆盖当前展开、已挂载或非忽略条目。
- 结果必须报告文件数、目录数、总字节数、忽略/隐藏内容、符号链接、嵌套 Git 根或子模块、打开文档和是否因预算被截断。
- 被截断的子树不能继续执行递归修改；菜单或确认界面必须说明需要缩小范围或使用系统文件管理器。
- 符号链接自身可以在未来作为一种明确条目处理，但递归操作不能跟随链接越出工作区。
- 文件夹不能被复制或移动到自身或任意后代目录中。
- 移动或重命名文件夹必须一次性重映射所有后代文件身份、打开标签、搜索结果、选择和展开键；无法完整重映射时，在磁盘写入前拒绝。
- 删除文件夹的确认界面显示预检计数，并明确提示不在当前 Files 投影中的隐藏或忽略内容也会随整个目录进入回收站。

### 动作行为

#### 新建文件…

1. 菜单关闭。目标是文件时，在其父目录下显示行内文件名输入框；目标是文件夹时，在该文件夹内部显示输入框并保证它处于展开状态。
2. 只接受一个文件名，不接受绝对路径、路径分隔符、`.`、`..`、NUL 或平台不支持的名称；点文件名和 Unicode 名称在文件系统允许时有效。
3. `Enter` 提交，`Escape` 取消。失去焦点不能在没有明确结果的情况下创建文件。
4. 后端要求实际创建目录仍属于当前授权工作区且不是符号链接路径，目标必须不存在；绝不覆盖同名文件。
5. 成功后通过版本化工作区重整更新目录树，保持原有展开和滚动状态，选中新文件并在编辑器中打开它。
6. 失败时保留输入和焦点，显示具体原因；用户可以修改名称或取消。

创建结果是零字节普通文件。创建目录和从模板创建文件不属于本草稿。

#### 剪切、复制和粘贴

本草稿假定先提供 **Asterlyn 内部文件操作剪贴板**，不宣称已经与操作系统文件剪贴板互通。是否支持跨 Asterlyn 窗口、跨项目或系统文件管理器粘贴，在所有功能区完成后统一审查。

- 剪切和复制记录操作种类、精确源条目身份，以及文件源版本或文件夹预检身份，不立即修改磁盘。
- 剪切目标及其当前可见后代获得弱化但仍可辨识的待移动外观；取消剪贴板、源条目变化或成功粘贴后清除该状态。
- 目标是文件时，“粘贴”表示粘贴到该文件的父目录；目标是文件夹时，表示粘贴到该文件夹内部。
- 粘贴执行时重新授权源和目标目录。文件版本或文件夹预检身份变化时要求重新复制/剪切，不能默默使用与用户选择时不同的内容。
- 剪切到原目录是成功的无变化结果并明确提示；复制到原目录会进入同名冲突处理。
- 目标同名文件永远不会被静默覆盖。初始安全行为是保留现有文件并要求选择新名称或取消；是否增加明确的“替换”选项留到全局实施审查。
- 复制/移动文件夹时执行上述递归预检，并拒绝把目录放入自身或后代。跨设备移动必须使用受监督的复制、验证、再删除流程；复制失败不能删除源条目。
- 成功后统一重整 Files、打开标签、Search 和 Git 状态。移动文件夹时必须迁移所有受影响标签身份并保留内容、选择、撤销历史和脏状态；无法安全迁移时，在写入前拒绝并说明原因。

#### 在文件管理器中显示

- 仅接受当前工作区中重新验证过的文件或文件夹身份，不能成为打开任意系统路径的通用命令。
- 文件目标在 macOS 请求 Finder 显示、在 Windows 请求文件资源管理器选择；文件夹目标直接打开该文件夹。Linux 在桌面能力允许时选择文件目标，否则打开其父目录并说明平台限制。
- 条目已经不存在时不打开旧路径，显示失败并请求一次定向工作区重整。
- 这是即时外部导航动作；成功不改变 Files 选择、编辑器文档或仓库状态。

#### 重命名…

1. 菜单关闭，目标行进入行内编辑。输入框显示完整文件或文件夹名；对普通带扩展名文件可默认选中文件名主体，但扩展名仍可编辑。
2. 名称验证与新建文件一致，目标必须位于原父目录。本动作不承担跨目录移动。
3. 后端绑定源版本、父目录身份和目标不存在条件，支持大小写不敏感文件系统上的仅大小写重命名，绝不静默覆盖。
4. 成功后选中新的稳定路径，并保持父目录展开、后代展开、滚动位置及焦点。
5. 重命名文件夹时，所有后代的打开标签和状态键一起迁移到新身份；干净或脏缓冲区、撤销历史和脏状态不能丢失。无法安全迁移时，在磁盘修改前阻止重命名。
6. Git 状态由后续权威读取判断是否为重命名，前端不自行宣布 Git rename。

#### 复制路径

- **文件名：** 条目身份的最后一个名称段，例如 `app.ts` 或 `src`；界面文案仍保持用户要求的“文件名”。
- **相对路径：** Files 树使用的工作区根相对路径，例如 `src/app.ts`；它不是嵌套 Git 根相对路径。
- **绝对路径：** 当前已授权工作区根与相对路径组合后的平台原生绝对路径。桌面适配层负责平台路径格式和最终验证。
- 每次成功都显示明确且本地化的“已复制文件名/相对路径/绝对路径”反馈；剪贴板权限失败时显示可恢复错误。
- 此二级菜单必须支持左右方向键、Escape 返回父菜单，以及指针向子菜单移动时的合理容错区域。

#### Git History

- 仅在文件目标已跟踪，或文件夹目标属于当前 Git 根且其路径下存在已跟踪内容时可用。
- 激活后打开底部 Git History，并以 `{ repositoryId, repository-relative path }` 作为唯一文件或文件夹路径过滤条件。
- 为避免旧筛选造成“没有历史”的误解，该入口使用默认的所有引用、所有作者和所有日期查询，再附加该条目路径；收藏和最近引用等用户偏好不被删除。
- 该路径记录到现有最近路径列表，History 行为、分页和提交详情继续由 Git History 功能负责。
- 当前 Git 查询使用精确路径且没有 `--follow`，因此第一版不会跨历史重命名追踪文件或文件夹。这是明确限制；若产品要求追踪重命名，需要单独扩展 Git 查询协议和测试，不能由右键菜单伪装实现。

#### 删除…

- 菜单项位于末尾并使用危险操作样式。激活后弹出包含文件/文件夹名和工作区相对路径的确认界面；文件夹还显示递归预检计数和隐藏内容提示。
- “删除”在本阶段始终表示移入系统回收站/废纸篓，不提供永久删除降级路径。
- 目标文件或文件夹后代中存在未保存文档时阻止删除，并引导用户先保存或取消；不能借删除动作丢弃内存缓冲区。
- 执行前复核文件版本，或复核完整文件夹预检身份、条目种类和非链接路径。目标变化或消失时拒绝旧确认。
- 成功后关闭受影响的干净标签，选择相邻可见条目，并通过版本化重整更新 Files、Search、Git 状态和活动文档。
- 回收站不可用、权限不足或桌面环境不支持时保留完整目标并报告失败，不回退为不可恢复的直接删除。

### 菜单生命周期和反馈

- 同一窗口同时只显示一个业务右键菜单；打开新菜单会关闭旧菜单及其二级菜单。
- 打开菜单本身应在下一帧可见。剪切、复制和复制路径通过选中状态或通知给出即时结果。
- 创建和重命名使用行内忙碌与错误状态；粘贴和删除在目标行或确认界面显示命名进度，并以成功、无变化、取消或失败结束。
- 仅改变状态栏文字不能作为这些动作唯一的反馈。
- 写入期间不允许对同一目标启动第二个互斥动作，但复制路径、查看 History 等安全读取可以继续使用。
- 工作区切换、窗口关闭和功能释放必须移除菜单、监听器、计时器、剪贴板中的失效窗口身份及未完成的展示状态。

### 无障碍和桌面习惯

- 菜单使用 `menu`、`menuitem`、`menuitemcheckbox` 或适当的子菜单语义，并发布 `aria-haspopup`、`aria-expanded` 和 `aria-disabled`。
- 打开后聚焦第一个可用项；上下键移动，Home/End 跳转，右键进入子菜单，左键返回，Enter/Space 激活，Escape 逐级关闭。
- 关闭菜单后把焦点还给仍存在的文件或文件夹行；若该行已被重整移除，则把焦点放回 Files 树稳定容器或新的有效选择。
- 菜单避开窗口边缘并在缩放、中文长文案及系统字体放大后保持可见。菜单不能让虚拟树无限增加已挂载行数。
- 快捷键只能在 Files 树拥有焦点且不会劫持编辑器或文本输入时生效。具体 `Ctrl/Cmd+X/C/V`、F2 和 Delete 映射留到全局键位审查。

### 验收草稿

实现阶段至少需要证明：

1. 右键和键盘在同一文件或文件夹上生成相同菜单，且不会同时打开文件或切换文件夹展开状态。
2. 虚拟滚动、树重整和工作区切换不会把动作发送给错误条目。

5. 大小写重命名、同名目标、跨设备移动、目录放入自身/后代和递归预算截断具有确定结果。

11. 每个用户动作符合统一反馈规范，并且功能释放后没有遗留监听器或菜单节点。
12. 相关前端测试、工作区/Rust 集成测试、桌面协议测试、`npm run check`、`npm run build` 和适用的 Cargo 测试通过，性能和已知限制写入接受证据。

## 草稿 C1：Changes 变更文件条目

### 目标

Changes 右键菜单服务于“理解一个变更、决定是否纳入提交、处理或恢复该变更”。它不复制 Android Studio 的 Changelist、Shelf 或 IDE 分析体系，也不绕过 Asterlyn 已建立的 checked-commit、可恢复 Revert 和冲突处理边界。

本草稿只覆盖 Changes 中的**单个文件行**。Changes 分组、投影出来的目录行、空白区域和提交编辑器将在后续草稿中单独判断。截图只用于枚举候选功能，不授权引入其图标、快捷键、术语或专属能力。

### 截图能力筛选

| Android Studio 候选 | 结论 | Asterlyn 处理 |
| --- | --- | --- |
| Commit File… | 不采用 | Asterlyn 从共享提交编辑器提交所有已勾选文件；单文件入口会重复提交表单并模糊现有勾选范围 |
| Rollback… | 首版必要 | 使用已有的“还原更改…”安全流程：预览、确认、精确状态复核和可恢复备份 |
| Move to Another Changelist… | 不采用 | 当前没有 Changelist 数据模型；提交勾选状态已经解决“本次提交包含什么” |
| Show Diff | 首版必要 | 复用当前完整 `HEAD` 到工作区 Diff，包括未跟踪文本和图片 Diff |
| Show Diff in a New Tab | 后续候选 | 当前只有一个可替换 Diff 预览；等编辑器组/多 Diff 标签模型成立后再评估 |
| Jump to Source | 首版必要 | 打开并在 Files 中定位当前工作区文件；已删除文件不可用 |
| Delete… | 条件性必要 | 仅为未跟踪文件提供“移到回收站…”；已跟踪文件的磁盘删除属于 Files 文件操作，不在 Changes 混入第二种语义 |
| Add to VCS | 不采用 | 普通提交刻意没有手动 stage 步骤；checked commit 会为选中的未跟踪文件安全地执行临时 intent-to-add |
| New/Edit Changelist… | 不采用 | 不建立 JetBrains 风格的并行变更列表数据库 |
| Create Patch from Local Changes | 后续候选 | Patch 文件导出有独立价值，但需要二进制、截断、目标路径和原子写入设计 |
| Copy as Patch to Clipboard | 后续候选 | 可与 Patch 导出共享模型，但需要大小上限、文本剪贴板和敏感内容反馈 |
| Shelve Changes… | 后续候选 | 若实现，应成为明确、可审查的 Git Stash 工作流，而不是产品私有 Shelf |
| Refresh | 菜单不采用 | Refresh 已位于 Changes 工具栏和项目级入口；它不是某个文件的上下文动作 |
| Local History | 不采用 | Asterlyn 不维护与 Git 并行的源码历史数据库；现有恢复材料是安全日志，不伪装为可浏览历史 |
| Git 子菜单 | 不采用通用入口 | 不提供含义不清的“Git”集合；首版直接提供明确的“Git History” |

### Asterlyn 首版菜单

从上到下使用以下顺序：

| 分组 | 菜单项 | 结果 |
| --- | --- | --- |
| 提交范围 | 包含在提交中 | 与文件行复选框共享一个勾选状态，不执行 Git stage |
| 查看 | 显示差异 | 在现有可替换 Diff 预览中打开完整本地差异 |
| 查看 | 跳转到源文件 | 打开当前文件并在 Files 树中定位 |
| 冲突 | 解决冲突… | 仅在当前操作快照允许处理该冲突时出现 |
| 处理 | 还原更改… | 对受支持的已跟踪文件或暂存新增文件执行可恢复还原 |
| 处理 | 移到回收站… | 仅在未跟踪文件上出现 |
| 路径 | 复制路径 › 文件名 | 复制名称 |
| 路径 | 复制路径 › 相对路径 | 复制工作区根相对路径 |
| 路径 | 复制路径 › 绝对路径 | 复制平台原生绝对路径 |
| 历史 | Git History | 打开该路径的 Git 提交历史 |

“解决冲突…”和“移到回收站…”是条件项；其余项目保持稳定位置。分隔线位于提交范围之后、查看之后、处理之后。危险的回收站动作在处理分组末尾显示危险样式。

### 打开和目标规则

- 鼠标右键命中变更文件行时，将它设为当前上下文选择并打开菜单，但不自动打开 Diff，也不改变“包含在提交中”的勾选状态。
- 键盘焦点位于变更文件行时，`Shift+F10` 或系统菜单键打开同一菜单。
- 菜单捕获完整的当前 `FileChange` 身份、所属仓库根、仓库修订、文件路径、原路径、当前提交包含状态和操作快照身份；不能只保存字符串路径或虚拟列表行节点。
- 当前 Changes 列表最多挂载 200 行。滚动、仓库替换、目标从最新快照消失或功能释放时关闭菜单，不能把迟到的动作发送给占用同一视觉位置的新行。
- 右键选中不同文件时，当前编辑器中的旧 Diff 保持原样，直到用户明确选择“显示差异”。如果现有控制器把选择与 Diff 清空绑定在一起，实现时必须拆开“上下文目标”和“打开 Diff”，不能让打开菜单造成编辑器闪空。

### 动作行为

#### 包含在提交中

- 使用带勾选状态的菜单项，和现有文件行复选框读写同一个 `excludedPaths` 投影。
- 激活只改变提交范围，不选择另一个文件、不打开 Diff、不执行 stage/unstage，也不修改工作区或索引。
- 新发现的普通变更默认包含；用户排除的仍存路径在普通重整后继续排除。
- 冲突文件保持包含且该项语义不可用，因为整个仓库必须先解决冲突才能提交；子模块可以被排除，以解除当前 checked-commit 的阻塞。
- 完成后立即更新菜单勾选、文件行复选框和提交按钮可用性，不只显示状态栏消息。

#### 显示差异

- 复用当前受限、可取消且拒绝过期 `FileChange` 的本地 Diff 读取。
- 差异范围是完整 `HEAD` 到当前工作区状态，而不是仅暂存区或仅未暂存区；这与 Asterlyn 的 checked-commit 语义一致。
- 未跟踪文本显示为新增文件 Diff，受支持图片显示前后预览，二进制和超限结果诚实降级。
- 该动作替换现有 Diff 预览，但不关闭持久文本标签，也不改变提交包含状态。

#### 跳转到源文件

- 对当前仍存在的文件，复用项目文件授权，打开已有或新的文本/图片标签，并在 Files 树中展开和选中其工作区路径。
- 已删除路径没有当前源文件，该项保持可聚焦但语义不可用，并说明可以查看 Diff 或使用“还原更改…”恢复它。
- 重命名使用当前路径作为源文件；原路径只作为 Git 变更身份的一部分。
- 文件不在当前有界项目目录、变成忽略只读身份或授权过期时，拒绝旧动作并触发定向重整。

#### 解决冲突…

- 仅当 `FileChange.conflicted` 且当前 Git 操作快照仍列出同一路径时出现。
- 激活现有 Base/Ours/Theirs 与结果编辑流程，继续使用修订令牌、Save and Stage、Resolve as Deleted 和可恢复工作区事务。
- 冲突来自未受支持或外部状态、没有可恢复操作快照时，不伪造内部解决能力；界面说明需要外部 Git 工具或完成状态重整。

#### 还原更改…

- 保留现有窄语义：恢复所选已跟踪文件的索引和工作区到当前 `HEAD`；暂存新增文件因为不在 `HEAD` 中，会在明确提示后从索引和工作区移除。
- 执行前显示文件名、当前/原路径及动作影响，生成精确计划并再次验证 `HEAD`、完整 `FileChange`、工作区字节和索引状态。
- 写入前发布应用本地恢复材料；成功后的 Undo 仍受记录的 `HEAD`、文件和索引版本约束。
- 未跟踪、copied、conflicted、submodule、unborn HEAD 或匹配的脏编辑器缓冲区保持不可用，并显示对应原因。
- 该动作不是任意 reset、不是 `git clean`，也不会恢复多个未明确选择的文件。

#### 移到回收站…

- 只在 `worktreeStatus === "untracked"` 的文件上出现，用于填补“还原更改”刻意不删除未跟踪文件的空白。
- 复用 Files 草稿中的已授权、版本检查和系统回收站能力；含未保存缓冲区时阻止执行。
- 成功后通过版本化重整移除 Changes 和 Files 中的该身份；失败时保留文件和行，不回退为 `git clean` 或永久删除。
- 已跟踪的修改、新增、删除、重命名和冲突行不显示此项。若用户希望删除实际文件，应从 Files 功能执行，以避免把“还原更改”和“删除文件”混为一谈。

#### 复制路径

- 三个值及反馈行为与 Files 草稿完全一致，并通过当前仓库根和项目目录把仓库相对 `FileChange.path` 映射为工作区相对路径。
- 对已删除文件仍可复制其最后已知路径；绝对路径表示该文件原本或将被恢复的位置，不宣称磁盘上仍存在文件。
- 对重命名文件复制当前路径。原路径保留在 Diff 和还原确认信息中，不在第一版增加第四个路径菜单项。

#### Git History

- 对已有提交历史的修改、删除和重命名路径可用；暂存新增和纯未跟踪文件尚无该路径的历史，因此不可用。
- 激活后打开底部 Git History，重置临时作者、日期和引用筛选，并安装该文件所属 `{ repositoryId, path }` 查询；收藏和最近引用偏好不被删除。
- 未提交重命名使用当前路径和 `originalPath` 两个精确过滤路径，使现有历史仍能包含旧名称下的提交；界面仍以当前文件名作为入口标签。
- copied 状态不会把源文件历史冒充为新文件历史；如果新路径没有提交记录，显示诚实的空结果。
- 当前查询不使用 `--follow`，所以除本次 `originalPath` 补充外，不跨更早的多次重命名追踪。

### 状态与反馈

- 打开菜单后，行选择是立即可见的反馈；明确激活动作后再进入 Diff、源文件、冲突或确认界面。
- 提交范围切换在下一帧更新复选框和提交可用性。Diff 显示命名加载状态并以成功、截断、无文本差异或失败结束。
- 还原和回收站动作使用独立确认与忙碌状态；关闭菜单本身不是操作成功反馈。
- 若状态在菜单打开后变化，控制器依据最新规范状态更新或拒绝动作，并说明“变更已改变，请重新操作”；不能对旧 `FileChange` 自动重试写入。
- 当前另一个 Git/工作区写入占用同一仓库时，修改动作保持可聚焦的语义不可用状态；复制路径和查看已缓存内容等安全展示不应被无关阻塞。

### 当前能力与新增依赖

当前项目已有：

- `ChangesCommitController` 对单个 `FileChange` 的选择、提交包含、Diff 请求、可恢复还原和过期结果拒绝；
- 变更文件、目录和分组复选框，以及树/平面投影和 200 行挂载上限；
- 完整本地文本/图片 Diff、Files 路径定位、Git History 路径查询和操作冲突编辑；
- checked commit 对未跟踪文件的临时 intent-to-add，以及保留无关索引状态的精确提交边界；
- 还原前恢复记录和失败后的权威 Git 状态重整。

本次实现已补齐：

- Changes 文件行右键入口、独立上下文目标和菜单状态；
- 从 Changes 直接跳转并定位源文件、复制三类路径和安装文件 History 查询的动作；
- 通过 R5 系统回收站处理未跟踪文件，且不会回退到 `git clean`。

仍未规划为首版能力的是多 Diff 标签/编辑器组、Patch 导出和受监督 Git Stash 工作流。

### 验收草稿

1. 右键和键盘在同一变更文件上得到同一菜单，不自动打开 Diff 或改变提交勾选。
2. 菜单动作绑定完整 `FileChange` 和仓库修订；刷新、虚拟滚动和仓库切换不能重定向旧动作。
3. “包含在提交中”与现有复选框保持单一状态来源，且从不执行手动 stage/unstage。
4. 文本、图片、未跟踪、删除和重命名文件的“显示差异”与现有完整本地 Diff 一致。
5. “跳转到源文件”不会为已删除或未授权路径创建虚假文件。
6. 冲突入口只在当前操作快照允许时进入现有可恢复解决流程。
7. 还原继续拒绝未跟踪、copied、conflicted、submodule、unborn 和脏缓冲区状态，并保留恢复证据。
8. 未跟踪文件只通过系统回收站删除；失败不调用 `git clean`、不永久删除、也不让界面提前消失。
9. Git History 使用正确的嵌套仓库身份；未提交重命名包含当前及原路径，纯未跟踪文件给出明确不可用原因。
10. 被排除的 Android Studio 能力不会以占位、空子菜单或无效按钮进入产品。
11. 英文、中文、菜单键、焦点恢复、屏幕边缘和 200 行虚拟列表场景通过交互检查。
12. 功能实现后补充 Changes 控制器/视图测试、Git 与工作区集成测试、桌面协议测试、完整检查、构建和接受证据。

### 后续产品与实施问题

- Changes 功能拥有上下文目标与行高亮，向共享菜单宿主提供一次性不可变身份；宿主不保存或推导 `FileChange` 状态。
- “显示差异到新标签”应等待完整编辑器组，还是允许较早引入多个只读 Diff 标签。
- Patch 导出是 Changes 专属应用服务，还是 Diff/History/Push 共同的导出能力。
- Git Stash 首版是否允许按单文件/路径保存，以及如何处理未跟踪文件、索引状态、冲突和恢复。
- Files 与 Changes 共享菜单宿主、文本剪贴板、类型化 History 导航和 R5 回收站应用服务，但各自拥有目标、可用性、选择和菜单组合。

## 草稿 B1：Branches 分支条目

### 目标

Branches 右键菜单服务于“查看某个分支、以它为起点开展工作，以及把它安全地用于当前分支”。它不是对 Git 命令全集的包装，也不能把本地引用修改、工作区切换和网络写入混成一次未经审查的动作。

本草稿只覆盖底部 Git 管理面板中的**本地分支和远程跟踪分支行**。Tag、远程仓库分组、提交行、历史图和空白区域分别留给后续草稿。截图只用于提供候选能力；Asterlyn 会补入自身工作流必需但截图当前分支菜单没有显示的动作。

### 截图能力筛选

| Android Studio 候选 | 结论 | Asterlyn 处理 |
| --- | --- | --- |
| New Branch from… | 首版必要 | 从右键目标的精确提交创建并切换到新的本地分支；不能继续使用当前仅从 `HEAD` 创建的窄实现来伪装 |
| Show Diff with Working Tree | 不采用 | 当前分支与工作区的差异已经由 Changes 完整表达；对其他分支又无法直观说明基准是分支尖端、当前 `HEAD` 还是 merge-base |
| New Worktree from… | 后续候选 | Git linked worktree 需要路径选择、共享 Git 目录锁、已检出分支保护、项目窗口归属和移除/修复流程，不能只是执行一个命令 |
| Update | 首版必要，限当前分支 | 复用现有 Update 方法选择和二次计划审查，不为未检出的分支执行后台整合 |
| Push… | 首版必要，限当前分支 | 复用现有 Push 精确预览、目标远程、标签和 force-with-lease 审查 |
| Tracked Branch… | 首版不提供修改 | 继续显示当前上游信息；“设置/更换上游…”作为后续独立工作流，而不是一个含义不清的级联菜单 |
| Rename… | 首版必要，限本地分支 | 精确改名本地引用；不暗示远程分支也已改名，不把远程改名伪装成本地操作 |

“与当前分支比较…”可作为将来的明确替代项：它只比较两个已提交的精确对象，不混入工作区，并需要面向多文件的提交范围 Diff 导航后再引入。

第二张远程分支截图补充筛选如下：

| Android Studio 远程分支候选 | 结论 | Asterlyn 处理 |
| --- | --- | --- |
| Checkout | 首版必要，但明确化 | 若已有唯一的对应本地跟踪分支则切换到它；否则显示“检出为本地分支…”，由用户确认本地名称并设置上游；永不进入 detached `HEAD` |

| Compare with current | 后续候选 | 改为明确的 commit-to-commit“与当前分支比较…”，等待多文件范围 Diff |

| Pull into current using Rebase/Merge | 菜单不采用 | 这是现有 Update 的两种策略；继续从当前本地分支或顶栏进入，避免建立第二套 Fetch、上游和远程路由 |
| Delete | 首版不提供 | 远程删除是特殊 Push 网络写入，留给未来独立审查；不能作为普通本地删除 |

右键菜单根据目标身份生成，条件不适用的项目不显示。处于临时阻塞状态但概念上适用的项目保持可聚焦的语义不可用状态，并说明原因。

远程分支第一版不提供 Rename、Delete、Push 或 Pull。远程分支并不是可直接改名的本地对象；远程删除是一次特殊 Push 网络写入，应在将来通过独立精确预览和确认实现，不能藏在普通删除中。Pull 已由当前本地分支的 Update 流程表达，不能再根据右键目标临时发明另一条上游路由。

### 逻辑分支与仓库目标

Asterlyn 当前会把已启用 Git 根中“种类和完整引用相同”的行合并为一个逻辑分支。这适合跨根查看历史，却不足以授权单仓库写入。

- 右键打开菜单只建立独立的上下文高亮，不立即切换 History 筛选、不检出分支，也不打开详情。
- “查看分支历史”继续使用逻辑身份，可同时查询所有当前启用且匹配的 Git 根。
- 一个逻辑行匹配多个 Git 根时，菜单标明它匹配的仓库数量，第一版只提供“查看分支历史”和两个复制项。切换、创建、Merge、Rebase、Update、Push、Rename 和 Delete 不显示，并说明必须先在高级引用选择中限定一个仓库。
- 即使逻辑行只匹配一个嵌套 Git 根或子模块，第一版仍只读；现有分支写入边界只授权顶层项目仓库。以后开放嵌套根写入时必须显式展示仓库名并单独审查。
- 单仓库动作捕获 `repositoryId`、分支种类、完整引用、短名称、所选对象 ID、是否当前分支、上游身份和工作区世代；不能只从显示名称反推目标。
- 菜单打开后引用移动、消失、改变种类、工作区切换或仓库世代变化时，读取动作重新解析，写入动作拒绝旧身份并要求重开；绝不把同名新引用当成已审查目标。

### 动作行为

#### 查看分支历史

- 复用分支行当前的逻辑引用查询，作用于 Paths 控制中已启用的 Git 根，不修改工作区、`HEAD` 或引用。
- 如果该逻辑分支已经是唯一筛选，再次选择本菜单项仍保持该筛选；“恢复所有引用”继续由现有分支选择交互或 History 控件负责，不让同一个菜单项承担切换语义。
- 查询只接受快照中已验证的完整引用及其精确对象 ID，异步结果继续按请求世代、仓库根和引用身份拒绝过期响应。

#### 切换到分支

- 仅用于顶层仓库中非当前的本地分支，复用现有保存脏标签提示、完整工作区清洁检查和 Git 边界二次验证。
- 已跟踪、暂存、冲突或未跟踪内容，以及未完成的未跟踪扫描、活动 Git 操作和互斥仓库写入都会阻止切换；第一版不自动 stash、不自动丢弃，也不允许 Git 猜测同名远程分支。
- 执行时重新确认目标完整引用仍存在且仍指向菜单捕获的对象。成功后以权威快照更新 `HEAD`、Changes、Files、History、上游和远程动作；失败不预先改变界面分支状态。

#### 从此处新建分支…

- 对顶层仓库中的本地或远程跟踪分支显示输入界面，明确写出起点短名称、引用种类和精确提交缩写；当前分支、其他本地分支和远程分支使用同一流程。
- 名称必须通过 Git 引用格式验证，目标 `refs/heads/<name>` 必须不存在，不能接受选项形名称、空引用段、`@{-1}` 或模糊修订表达式。
- 提交时重新验证起点引用和对象，要求与切换分支相同的完整清洁状态，再以一个受监督动作从该精确对象创建并切换到新分支。起点在期间移动时拒绝，不悄悄改用最新提交或当前 `HEAD`。
- 新分支不自动继承起点的上游；本地或远程起点都只是提交来源。例如从 `origin/main` 新建 `feature/menu` 不会让该功能分支跟踪 `origin/main`。成功后通过新快照确认新引用和实际 `HEAD`，不能只因 Git 进程退出成功就提前宣布完成。

#### 切换到对应本地分支 / 检出为本地分支…

- 仅用于顶层仓库中的远程跟踪分支。Asterlyn 先通过本地分支的规范上游配置寻找对应关系，不能仅因短名称相同就猜测。
- 若恰有一个本地分支跟踪该远程引用且它不是当前分支，显示“切换到本地分支 `<name>`”；若它已经是当前分支则不显示检出项。多个本地分支都跟踪同一远程引用时不替用户任选一个，改为显示选择界面。
- 如果没有对应本地跟踪分支，显示“检出为本地分支…”。界面列出远程名、远程分支名、精确对象和建议本地名称；建议名称移除一次远程前缀，例如 `origin/feature/menu` 建议为 `feature/menu`，用户可以修改且目标本地引用必须不存在。
- 新建式检出明确把上游设置为右键远程分支；切换到已有本地分支则保留其现有配置。两种情况都要求完整清洁工作区，并重新验证本地/远程引用和对象。
- 该动作不会先联网 Fetch，因此使用界面标明的最后获取状态；需要服务器最新状态时，用户应先对该远程执行 Fetch。Asterlyn 永不通过该入口检出远程对象为 detached `HEAD`。
- 任一步骤结果不确定时，Asterlyn 刷新 Git 真相并说明已观察到的本地分支、`HEAD` 和上游状态；不能盲目重试创建。

#### 合并到当前分支… / 将当前分支变基到此处…

- 仅对顶层仓库中不是当前分支的精确本地或远程跟踪引用显示，并复用现有 reviewed Git-operation 生命周期。
- 激活只打开计划读取和审查，不立即改变历史。计划绑定当前完整分支引用、起始 `HEAD`、目标完整引用及对象、提交范围、清洁工作区和不处于其他 Git 操作的条件。
- Merge、Rebase 的可执行关系、冲突继续/跳过/中止、恢复和过期计划拒绝都继续由现有 Git operation 功能负责；菜单不增加自动 stash、自动 force push 或隐式策略回退。

#### Update… / Push…

- 只在右键目标经最新快照确认为顶层仓库的当前本地分支时适用，菜单只是现有顶栏动作的第二入口，不拥有另一套策略或状态。
- Update 仍要求受支持的已配置上游、完整清洁工作区和所选顶栏远程与上游一致；它先选择 Fast-forward、Merge 或 Rebase，再按现有规则 Fetch 并在需要时执行第二次精确计划确认。
- Push 仍以顶栏所选远程为作用域，打开包含来源、目标、提交、文件、标签和明确 force-with-lease 的现有预览。菜单激活绝不直接联网写入。
- 若菜单打开后当前分支、上游或所选远程变化，动作保持可聚焦但拒绝旧路由，并引导用户根据最新信息重开；不能自动切换远程。

#### 重命名…

- 仅用于顶层仓库中的本地分支。输入框默认选中完整短名称并使用与新建分支相同的引用格式验证；目标引用必须不存在。
- 执行前重新确认旧完整引用、精确对象、当前 `HEAD` 身份、活动 Git 操作和该分支未在另一个 linked worktree 中检出。改名本身不要求清空未提交文件，但不能与其他仓库写入并发。
- 当前分支改名必须通过权威结果确认符号 `HEAD` 已指向新引用；非当前分支改名不能切换当前工作区。
- 本地改名不重命名、不删除也不创建远程分支。原有上游若仍有效则保留，并在结果中明确显示本地新名称仍跟踪哪个远程分支，避免用户误以为远程名称同步变化。
- 动作绑定旧引用及其对象，期间引用移动时拒绝；不能把后来出现的同名引用改名。

#### 复制分支

- “简短名称”复制当前界面使用的分支名；本地示例为 `main`，远程跟踪示例为 `origin/main`。
- “完整引用”复制规范 Git 引用，例如 `refs/heads/main` 或 `refs/remotes/origin/main`。复制的值来自已验证身份，不从本地化显示文本或远程树缩进拼接。
- 成功和剪贴板失败都提供明确反馈；该动作不需要单仓库写入授权，多根逻辑分支因完整引用一致也可使用。

#### 删除本地分支…

- 只对顶层仓库中非当前的本地分支显示。确认界面列出短名称、完整引用、精确对象、与当前分支的合并关系及可能存在的上游；“删除本地分支”不删除远程分支。
- 第一版只允许安全删除：目标提交已经包含在当前 `HEAD` 可达历史中，目标未被任何 linked worktree 检出，且引用和对象与确认时完全一致。未合并分支显示原因并拒绝，不提供 force delete 复选框或隐藏快捷键。
- 删除不要求工作区清洁，但活动 Git 操作和同仓库互斥写入会阻止执行。Git 边界使用精确旧对象作为引用删除前提，外部进程移动目标时失败关闭。
- 成功后刷新引用和 History，清理已失效的分支筛选、收藏或最近引用展示状态，但不删除任何提交对象、工作区文件、上游远程分支或产品私有数据库记录。

### 后续候选与明确不支持

- **后续候选：Git Worktree。** 从分支创建 linked worktree 需要独立的创建、打开、锁定、移动、移除、修复和脏工作区保护设计。当前“Git worktree recovery”只是操作恢复材料，不是 Git linked worktree 管理能力。
- **后续候选：设置/更换/取消上游。** 应通过显示本地来源、远程、目标引用和后续 Update/Push 路由的明确表单实现，并处理远程不存在、同名引用、已有上游和配置写入失败；不照搬 `Tracked Branch` 黑盒子菜单。
- **后续候选：与当前分支比较。** 等多文件范围 Diff 能承载精确 commit-to-commit 比较后再加入；不会把脏工作区内容混入比较。
- **后续候选：删除远程分支。** 必须成为特殊 Push 审查，显示精确远程、完整目标引用和最后获取对象，并清楚说明远程结果可能不确定。
- **明确不支持：后台 Update 非当前分支。** 未检出分支的 Fetch 可以更新远程跟踪引用，但 Asterlyn 不在隐藏工作区中替用户 Merge/Rebase 本地分支。
- **明确不支持：本地切换时猜测同名远程、detached 远程检出、Checkout 后自动 Rebase、自动 stash、自动 force push、强制删除未合并分支和把远程 Rename 包装成删除加重建。** 这些都会掩盖实际发生的历史或网络变化。
- **远程分支菜单不提供 Pull using Merge/Rebase。** 这两个入口与当前本地分支的 Update 策略完全重叠，却会让用户误以为任意远程跟踪引用都可临时成为 Pull 上游。Update 继续依赖已配置上游和顶栏所选远程。
- **不在分支菜单重复 Fetch/Refresh。** Fetch 属于所选远程且更新其完整标准跟踪命名空间；Refresh 是项目级本地重整，都不是单分支动作。

### 当前能力与新增依赖

当前项目已有：

- 本地、远程和 Tag 引用列表，以及跨已启用 Git 根的逻辑分支 History 查询；
- 顶层仓库的安全本地分支切换，以及在干净工作区从当前 `HEAD` 创建并切换本地分支；
- 分支详情中的 Merge、Rebase 入口和完整 reviewed Git-operation 生命周期；
- 当前分支的 Update、Push、远程选择、上游读取、精确计划/预览及网络取消流程；
- 仓库作用域的互斥写入、权威状态重整和过期结果拒绝。

本草稿初审时列出的以下缺口，已在 2026-09-15 的 CM3 分支交付中补齐：

- 分支行右键入口、独立上下文目标和适用于逻辑/精确分支的菜单状态；
- 从任意精确本地或远程分支对象创建普通本地分支，而不是固定从当前 `HEAD` 创建；
- 解析远程分支对应的本地跟踪分支，以及从远程跟踪分支安全检出本地分支并设置上游；
- 本地分支 Rename、安全 Delete 及 linked worktree 检出保护；
- 分支名称文本剪贴板动作。

仍明确留待后续的是 Git linked worktree 管理、上游配置、commit-to-commit 多文件比较和远程分支删除审查。

### 验收草稿

1. 右键和键盘在同一分支行得到相同菜单，打开菜单不切换 History 筛选、不检出分支，也不触发网络。
2. 本地当前、其他本地、远程、多根逻辑、嵌套 Git 根和已消失引用得到正确且可解释的菜单状态。
3. 所有单仓库写动作绑定根限定完整引用和精确对象；引用在菜单或确认期间移动时拒绝而不是改用新目标。
4. 切换、本地起点新建和远程检出在前端及 Git 边界都重复完整清洁检查，且不自动 stash、丢弃或猜测远程。
5. 从其他本地或远程分支新建确实使用所选对象而非当前 `HEAD`，且不继承起点上游；远程检出使用标明的最后获取对象并设置正确上游。
6. Merge 和 Rebase 只打开现有精确计划审查，冲突及恢复行为不被菜单绕过。
7. Update 和 Push 与顶栏共享一套远程选择、策略、预览、可用性和取消状态；菜单入口不会直接执行网络写入。
8. Rename 正确处理当前/非当前本地分支、名称冲突、旧对象变化和其他 worktree 检出，并诚实保留或报告原远程上游。
9. Delete 永远拒绝当前、未合并、对象已变化或被其他 worktree 检出的分支；不会删除远程引用或工作区文件。
10. 多根逻辑行不会意外选择一个仓库执行写入；嵌套 Git 根维持已记录的第一版只读边界。
11. 被排除的“与工作区比较”、隐式远程改名、后台更新和 force 能力不会以空入口进入产品。
12. 英文、中文、长分支名、层级分支名、键盘导航、屏幕边缘和焦点恢复通过交互检查；实现后补充分支视图/控制器、Git 核心、桌面协议、真实远程和多 worktree 接受证据。

### 后续产品与实施问题

- 逻辑分支右键写操作是保持只读，还是通过仓库二级菜单让用户显式选择一个根；后者会显著增加嵌套菜单和焦点复杂度。
- “查看分支历史”是保留在菜单中作为明确动作，还是因为普通点击已能完成同一件事而在最终精简时删除。
- 分支 Rename/Delete/Create 的计划与确认模型能否复用 reviewed Git operation 基础设施，还是应使用更轻量但同样精确的引用变更事务。
- Update/Push 按首版矩阵保留在当前分支菜单中，并与顶栏调用同一应用动作，不能互相点击界面。
- 远程“检出为本地分支”采用设置上游的明确语义；“从此处新建分支”采用不继承上游的明确语义。全局审查时确认这两个名称和表单是否足以避免混淆。
- Git Worktree、上游设置、远程分支删除和分支比较应按什么顺序进入后续里程碑。

## 草稿 H1：History 单条提交记录

### 目标

History 提交记录右键菜单服务于“识别这个提交、把它安全地应用到当前工作、或从它开始新的工作”。它不把一条不可变提交记录伪装成可以随意编辑的文档，也不提供未经预览的引用移动、历史改写或网络发布快捷方式。

### Asterlyn 首版菜单

从上到下固定为以下精简结构：

| 分组 | 菜单项 | 结果 |
| --- | --- | --- |
| 身份 | 复制提交 ID | 复制完整对象 ID |
| 应用 | Cherry-pick… | 打开单提交 Cherry-pick 计划审查 |
| 应用 | Revert Commit… | 打开创建反向提交的计划审查 |
| 开始工作 | 从此提交新建分支… | 从精确提交创建并切换到新本地分支 |

“复制提交 ID”之后和“Revert Commit…”之后显示分隔线。菜单没有危险操作区，因为首版不提供 Reset、Drop 或引用删除；Cherry-pick、Revert 和新建分支虽然会写入仓库，但都只打开命名预检/审查流程，不把右键激活视为最终执行授权。

普通点击已经负责选中提交并加载详情，因此菜单不重复“查看提交详情”。打开提交内某个文件的 Diff 继续由右侧提交文件列表负责。

### 打开和目标规则

- 鼠标右键命中真实提交行时，将它设为当前提交选择并打开菜单；允许右侧详情按现有懒加载规则更新，但不自动打开文件 Diff、不执行 Git 操作，也不改变 History 筛选。
- 键盘焦点位于提交行时，`Shift+F10` 或系统菜单键在该行附近打开同一菜单。
- 折叠线性历史的汇总行不是提交身份，右键不显示本菜单；用户先展开，再对具体提交操作。
- 菜单捕获根限定身份：工作区世代、`repositoryId`、完整对象 ID、按 Git 顺序排列的父对象、当前可见装饰和提交摘要。显示行号、短哈希、主题或虚拟列表 DOM 都不能成为动作身份。
- History 最多保留 100,000 条会话结果并虚拟挂载最多 200 个可见行。滚动导致行复用、分页替换、筛选变化、仓库刷新、工作区切换或功能释放时关闭菜单；不能把动作发送给后来占据相同视觉位置的提交。
- 对象 ID 是内容寻址身份，因此“复制提交 ID”可以复制捕获值；写动作仍需重新验证该对象在同一授权仓库中存在、类型为 commit，并重新读取所有当前分支和工作区前提。

### 仓库与可用性边界

- 顶层项目仓库的单条提交可使用全部首版菜单项，但写动作要求当前 `HEAD` 是本地分支、完整工作区已确认干净、不存在活动 Git 操作或互斥仓库写入。
- 嵌套 Git 根或子模块提交第一版只提供“复制提交 ID”。当前所有 Git 写动作仍限定顶层项目仓库，不能因为提交对象可读就扩大 mutation 授权。
- 当前工作区脏、未跟踪扫描尚未完成/失败、处于 detached 或 unborn `HEAD`、操作冲突中时，复制仍可用；概念上适用的写动作保持可聚焦的语义不可用状态并说明具体原因。
- 所选提交就是当前 `HEAD` 或已经可达时，Cherry-pick 可能没有效果；菜单不靠前端图形猜测，激活后由精确计划读取给出“已经包含/无可应用变更”的结果且不进入确认。
- Cherry-pick 和 Revert 的第一版只支持零或一个父提交。合并提交需要明确选择 mainline parent，在该选择界面实现前，两项均保持语义不可用并说明原因。

### 动作行为

#### 复制提交 ID

- 复制 Git 返回并验证过的完整十六进制对象 ID，例如 40 位 SHA-1；仓库以后采用其他受支持对象格式时复制其完整规范值，菜单不硬编码长度。
- 不默认复制短哈希，因为其唯一性随仓库增长而变化；界面仍可在行或通知中显示短形式帮助核对。
- 成功后显示“已复制提交 ID”；剪贴板不可用时保留菜单目标并显示可恢复错误。值不能从主题文字、装饰或本地化标签中解析。

#### Cherry-pick…

- 仅把当前根限定完整对象 ID作为一个目标预填到已有 reviewed Git-operation 控制器，然后打开计划读取；右键本身不运行 `cherry-pick`。
- 计划绑定规范仓库、当前完整分支引用、起始 `HEAD`、所选提交对象、提交数量、完整清洁工作区和无活动操作条件。执行前重复生成计划，令牌变化即拒绝。
- 保存中的编辑器标签先走现有 Save-or-Cancel 协调；任何仍然脏、暂存、冲突或未跟踪内容都阻止计划。第一版不自动 stash 或携带本地更改。
- 执行、冲突发现、Continue、Skip、Abort、重启恢复和文本冲突解决完全复用现有 Cherry-pick 生命周期。单条菜单入口不削弱已有多提交 Cherry-pick 能力，后者继续从 Git Operations 明确输入有序目标。

#### Revert Commit…

- 语义固定为“在当前分支创建一个新的反向提交”，不移动原提交、不重写已有提交、不等同于 Changes 的单文件“还原更改”，也不等同于 Reset。
- 激活先读取计划，显示当前分支、起始 `HEAD`、被反转提交、其父提交、受影响文件和将采用的提交消息，再由用户第二次确认。
- 计划和执行绑定同一根限定对象、当前分支、起始 `HEAD`、完整清洁工作区及无活动操作条件。对象或 `HEAD` 改变时拒绝，不能改为反转“现在位于这一行”的另一个对象。
- 执行应加入现有 Git-operation 生命周期：若产生冲突，Changes 显示冲突并只提供合法的 Continue 和 Abort；保存解决结果继续使用现有修订检查和可恢复工作区事务。第一版单提交 Revert 不需要 Skip。
- 合并提交在首版不可用。后续支持时必须要求用户选择 mainline parent，并在计划中同时显示父对象和主线含义；绝不默认选择 `-m 1`。
- 成功必须从权威快照确认 `HEAD` 产生了预期的新提交；失败或外部并发导致结果不确定时只重整和说明观察结果，不自动重试或回滚外部历史。

#### 从此提交新建分支…

- 显示新本地分支名称输入、所选提交主题和完整/缩写对象 ID。名称使用与 Branches 草稿相同的 Git 引用验证，目标引用必须不存在。
- 要求顶层仓库、当前本地分支和完整清洁工作区，并先处理编辑器脏标签。执行时重新验证对象和目标引用，再以一个受监督动作从该精确对象创建并切换到新分支。
- 新分支不从提交装饰推断或继承上游；即使提交由远程分支可达，它也只是起点。需要跟踪远程时使用远程分支的“检出为本地分支…”或后续明确的上游设置流程。
- 成功后通过权威快照确认新引用和实际 `HEAD`，并刷新 Changes、Files、History、分支选择和远程动作。创建或切换结果不确定时禁止盲目重试。

### 后续候选与明确不支持

- **Patch 导出。** 与 Changes 的 Patch 草稿统一设计普通 Diff 与 `format-patch` 两种产物、二进制和重命名表示、大小预算、原子保存、同名冲突和文本剪贴板。
- **与当前分支比较。** 只比较所选提交和当前 `HEAD` 两个精确已提交对象，不把索引或工作区混入“Local”；等待多文件范围 Diff 导航。
- **提交时刻的仓库浏览。** 使用独立只读文档/树身份、懒加载目录和对象大小限制，不把历史内容挂进可写 Files 树，也不允许保存覆盖当前工作区。
- **创建 Tag。** 需要先确定轻量与附注 Tag 的首版取舍、Tag 消息/签名和名称冲突；创建本地 Tag 与随后 Push 必须是两次独立授权。
- **父/子提交导航。** 父提交使用 Git 报告的有序父对象；子提交必须处理多个结果以及筛选、折叠、分页未加载状态，不能只扫描当前可见 DOM。
- **View in browser。** 需要 provider-neutral 远程地址适配，移除凭据和敏感 URL 片段，支持 SSH/HTTPS 与自托管实例，并明确外部导航失败。
- **现有 bounded Squash 不改语义。** 它仍表示把所选 first-parent base 之后、直到当前 `HEAD` 的最多 1,000 个提交压成一个提交，并通过精确旧 `HEAD` lease 更新当前分支；首版不把截图中的 per-commit “Squash Into…”映射到它。
- **不支持 detached Checkout、Reset、模糊 Undo、Fixup、Drop、编辑旧提交消息、交互式 Rebase 和 Push All up to Here。** 如果未来增加历史编辑器，它必须整体展示受影响提交序列、引用移动、恢复和远程后果，而不是逐个增加危险菜单快捷方式。

### 当前能力与新增依赖

当前项目已有：

- 根限定 `CommitSummary`、完整对象 ID、父对象、最多 100,000 条的分页会话结果和虚拟 History 行；
- 选中提交、懒加载提交文件、首父/空树 Diff、根限定文件 Diff 和过期结果拒绝；
- 精确单/多提交 Cherry-pick 的计划、二次确认、冲突 Continue/Skip/Abort 和重启恢复；
- 顶层仓库从当前 `HEAD` 创建并切换分支，以及 Branches 草稿规划的任意精确对象起点扩展；
- bounded Squash，但它当前只属于统一 Git Operations，不具有截图的 per-commit Squash 语义。

本草稿初审时列出的以下缺口，已在 2026-09-15 的 CM3 单提交交付中补齐：

- History 提交行右键入口、独立上下文身份、菜单状态和文本剪贴板动作；
- 从行菜单把精确对象预填到 Cherry-pick 审查；
- 可由 Asterlyn 发起、继续和中止的单提交 Revert 计划及协议；
- 从任意精确提交创建并切换分支；

以下能力仍留作后续候选：

- Patch 导出、commit-to-commit 多文件比较、历史提交树浏览、Tag 创建、可靠父/子定位和远程浏览器链接。

### 验收草稿

1. 右键和键盘在同一真实提交行得到相同菜单；折叠汇总行不会被误当成某个提交。
2. 菜单绑定 `repositoryId + oid` 而不是短哈希、主题、列表索引或虚拟 DOM；滚动、筛选、分页和仓库切换不能重定向动作。
3. 顶层与嵌套 Git 根得到正确菜单范围，子模块提交不能进入顶层仓库写操作。
4. 复制始终返回完整规范对象 ID并提供成功/失败反馈。
5. Cherry-pick 只打开绑定精确对象的现有计划审查，脏工作区、活动操作、无效对象和无效果计划不会进入执行。
6. Revert 通过新增提交保留历史，重复验证 `HEAD` 和对象，并在冲突后正确提供 Continue/Abort、重启恢复和文件修订保护。
7. 合并提交的 Cherry-pick/Revert 在没有 mainline 选择能力前被明确阻止，不默认选择父提交。
8. 从提交新建分支使用所选对象而非当前 `HEAD`，不继承装饰分支的上游，并在清洁检查与权威刷新后完成。
9. Reset、Undo、detached Checkout、旧提交编辑、Fixup、Drop、交互式 Rebase 和任意提交 Push 不会以占位或隐藏快捷键进入产品。
10. 英文、中文、长主题、根提交、合并提交、过期对象、跨越旧 3,000 行边界的分页、虚拟滚动、键盘导航、屏幕边缘和焦点恢复通过交互检查。
11. 实现后补充 History 列表/详情控制器、Git operation、分支创建、桌面协议、冲突恢复、真实仓库及安装平台接受证据。

### 后续产品与实施问题

- 单条提交 Revert 使用 ADR-0008 的共享 reviewed-operation 生命周期和一个更窄的 Revert 计划，必须补齐 Continue/Abort，而不是建立另一套操作协调器。
- 何时为 merge commit 的 Cherry-pick 和 Revert 增加 mainline parent 选择，以及如何显示父提交的分支/主题背景。
- 现有 bounded Squash 是否最终增加“从此提交之后压缩…”的清晰上下文入口，或继续只放在 Git Operations 总入口。
- 父/子导航、Tag 创建、Patch、提交树浏览、commit-to-commit 比较和浏览器链接的优先顺序。
- “复制提交 ID”与 Git Blame、提交详情、Push 审查共享无状态文本剪贴板与反馈端口，各功能区仍从自己的精确目标格式化内容。

## 草稿 H2：History 连续多选提交记录

### 目标与范围

连续多选菜单服务于“把一段明确的提交序列作为整体查看或操作”。它不能只因为几行在当前屏幕上相邻，就断言它们属于同一仓库、同一分支或一条没有缺口的提交链。

第一版范围是同一 History 查询结果中 **2–100 个真实提交行组成的连续可见区间**。`Shift+单击`、`Shift+方向键`或等价键盘动作扩展范围；普通单击恢复单选。`Ctrl/Cmd+单击`形成不连续集合、多段选择、跨折叠汇总行选择和超过 100 条的范围不在本草稿中。

“连续可见”只描述交互选择，不授权 Git 操作。筛选、排序、折叠、多根合并和多分支拓扑都可能让相邻行不存在直接父子关系；每个动作必须根据完整对象图再次判断可用性和顺序。

### 截图能力筛选

| Android Studio 候选 | 结论 | Asterlyn 处理 |

| Create Patch… | 后续候选 | 与单条提交和 Changes 共用未来 Patch 导出模型，不为多选先造另一种格式 |

| Show Repository at Revision | 不适用于多选 | 多个提交没有唯一仓库快照；单条提交的未来只读浏览入口足够 |
| Compare Versions | 首版必要，限两条 | 比较两个根限定精确提交，不混入 `HEAD`、索引或工作区 |

### Asterlyn 首版菜单

| 分组 | 菜单项 | 显示条件 | 结果 |
| --- | --- | --- | --- |
| 身份 | 复制提交 ID | 任意有效连续多选 | 按界面从上到下复制完整 ID，每行一个 |
| 查看 | 比较两个提交… | 恰好两条且属于同一 Git 根 | 打开精确 commit-to-commit 多文件比较 |

“比较两个提交…”在数量不是两条时不显示。Cherry-pick、Revert 和 Squash 对数量适用但仓库/拓扑/状态暂时不满足的情况，保留可聚焦的语义不可用状态并说明具体原因。Squash 位于末尾、与其他项分隔，并使用历史改写警示样式。

### 多选状态与菜单目标

- 多选状态由一个根限定锚点、一个活动端点和按当前展示顺序展开的不可重复 `repositoryId + oid` 列表组成。右侧提交详情始终展示活动端点，不尝试把多条提交文件合并成单条详情。
- 在已选范围内右键，保持整个范围并打开 H2 菜单；在范围外的真实提交上右键，清除范围并按 H1 单条菜单处理。
- 范围不能跨过折叠线性历史汇总行、尚未加载的分页边界或错误/加载占位。遇到这些边界时停止扩展并说明需要先展开或加载。
- 当前查询新增分页且所有已选身份仍存在时可保留范围；Branch、User、Date、Paths、排序、折叠或根选择变化会创建新的展示序列并清除范围，避免隐藏选择。
- 菜单捕获查询世代、展示顺序、每个提交的根限定完整对象 ID 和父对象列表。虚拟列表最多挂载 200 行，滚动卸载行不能丢失范围身份，也不能把动作绑定到 DOM 区间。
- 打开菜单后若工作区切换、查询世代变化、任一对象消失或操作开始，菜单关闭或写动作拒绝。不可变对象仍存在并不代表当前分支、工作区清洁状态或可达关系仍与预检相同。

### 统一预检结果

Cherry-pick、Revert 和 Squash 共用一次只读的多提交选择分析，但各自拥有独立结论。分析结果至少包括：

- 所有选择是否属于同一 Git 根，以及是否为顶层项目仓库；
- 每个对象是否仍存在且类型为 commit；
- 展示顺序、提交时间和实际父子关系，不从日期推导拓扑；
- 选择是否构成由直接 first-parent 边连接的完整无缺口线性段；
- 是否包含 merge commit、根提交或当前查询未展示的中间提交；
- 该线性段与当前完整分支引用和精确 `HEAD` 的关系；
- 工作区、未跟踪扫描、活动操作和互斥写入状态；
- 针对每个动作的执行顺序、提交数量、无效果原因和阻塞原因。

预检只解释可用性，不是执行授权。打开具体计划后，Git 边界必须用相同精确对象和新的仓库状态重复分析；任何差异都会使计划过期。

### 动作行为

#### 复制提交 ID

- 按 History 当前界面从上到下的顺序复制完整对象 ID，每行一个并以平台文本换行连接。这个顺序可能是从新到旧，也可能受 History 排序影响；成功提示明确显示复制数量。
- 复制文本只是身份列表，不宣称可直接作为 Cherry-pick/Revert 命令顺序。Git 操作使用各自计划中明确显示的拓扑顺序。
- 跨 Git 根可以复制；相同对象 ID 在不同根中会按所选行分别保留。若用户需要根信息，应使用未来的结构化导出，而不是悄悄改变“复制提交 ID”的内容。

#### 比较两个提交…

- 只在恰好选择两个且属于同一 Git 根时显示。比较身份是 `{ repositoryId, beforeOid, afterOid }`，两侧都必须是完整、仍存在的 commit 对象。
- 如果一个对象是另一个的祖先，自动把祖先作为 Before、后代作为 After；如果两者位于分叉历史，使用锚点作为 Before、活动端点作为 After，并在界面提供显式“交换两侧”。
- 结果显示两个精确树之间的完整净文件范围，再按需打开单文件文本/图片 Diff；不把中间提交列表、当前 `HEAD`、索引或工作区内容冒充比较边界。
- 读取沿用现有 Diff 的取消、输出限制、树/平面显示、图片边界和过期请求拒绝，但需要新增任意两个提交树之间的文件清单及文件 Diff 协议。

#### Cherry-pick 所选提交…

- 第一版要求选择位于顶层项目仓库、每条均非 merge commit，并由直接父子边构成一条无缺口线性链。可见相邻但来自不同分支、不同根、含 merge commit 或漏掉中间提交时不可用。
- 计划按拓扑从最旧到最新排列精确对象，与 History 当前上下顺序无关，并在确认界面逐条显示序号、短 ID 和主题。用户确认的是这个有序列表，而不是选择矩形。
- 复用已有最多 100 个目标的 Cherry-pick 计划、精确 `HEAD`/目标令牌、清洁工作区检查、Continue/Skip/Abort、重启恢复和冲突编辑。右键动作只用选区预填计划，不直接执行。
- 计划若发现所选补丁已经包含、对象变化或顺序不再成立，保持选区并显示无效果/过期原因；不删除项目认为“重复”的某一条后继续执行剩余提交。

#### Revert 所选提交…

- 第一版要求所有提交属于顶层项目仓库、均非 merge commit，并且构成当前分支 first-parent 历史中的一段直接、无缺口序列；位于其他分支或只通过 merge parent 可达的选区不可用。
- 计划按最新到最旧反转，使后加入的变化先被撤销。确认界面同时显示原 History 选区顺序和实际 Revert 顺序，避免用户把它与 Cherry-pick 顺序混淆。
- 语义是为每个目标创建对应的反向提交，保留原提交和当前分支历史。计划绑定当前分支、起始 `HEAD`、全部目标/父对象、执行顺序、工作区状态和预计影响文件。
- 多提交 Revert 扩展 H1 的 reviewed Revert 生命周期：冲突时 Changes 显示当前目标和整体进度，并提供合法的 Continue、Skip 和 Abort；Skip 只跳过计划中当前明确的反转目标。
- 任一对象、当前分支或 `HEAD` 变化会使整个计划过期，不自动缩小为仍然有效的子集，也不在部分失败后从头盲目重试。

#### Squash 所选提交…

- 只有同时满足以下条件时可执行：全部提交属于顶层项目仓库；数量至少两条；均位于当前分支直接 first-parent 链；选区最新一条就是精确 `HEAD`；选区内部无缺口、无 merge commit；最旧一条之前存在一个明确 first-parent base。
- 筛选或折叠隐藏了选区内的提交、选区只是当前分支中间一段、包含其他分支提交、包含根提交而没有可保留 base，都会阻止该入口。第一版不通过交互式 Rebase 改写中间历史。
- 界面显示保留的 base、被替换的完整提交列表、当前 `HEAD`、最终树、提交数量和新提交消息。执行复用现有 bounded Squash，并继续受最多 1,000 个 first-parent 提交和精确旧 `HEAD` lease 保护；H2 的显式选择上限仍为 100 条。
- Squash 创建一个使用已审查 `HEAD` 树的新提交，并仅在当前分支仍等于审查的旧 `HEAD` 时安装它。它不运行 broad reset、不修改其他分支、不自动 force push，也不删除仍被其他引用保留的对象。
- 选择范围与后端从 base 到 `HEAD` 重新计算的完整提交集合不完全一致时拒绝，不能悄悄把未选择的隐藏提交一起压缩。

### 后续候选与明确不支持

- **多提交 Patch 导出**继续等待共享 Patch 模型；未来若采用 `format-patch`，必须保留明确顺序和一提交一邮件语义，不能与两个树之间的合并 Diff 混称为同一文件。
- **任意不连续 Cherry-pick**需要带拖拽/键盘重排的有序清单和依赖提示。现有 Git Operations 仍可接收用户明确输入的有序目标，但 H2 第一版不根据不连续图形选择猜顺序。
- **中间范围 Squash、Drop、Fixup、Edit Message 和交互式 Rebase**属于同一个未来历史编辑器；需要展示完整 todo 序列、所有受影响后继提交、冲突/中止恢复和远程发布后果。
- **多选不提供仓库快照浏览、New Branch、New Tag、父/子跳转或 View in browser。** 这些都需要唯一目标；用户应先保留一个活动提交并回到 H1。
- **不提供 Reset 或 Push All up to Here。** 选择矩形既不是分支引用也不是远程发布范围，不得被转换成隐藏的引用移动或网络写入。

### 当前能力与新增依赖

当前项目已有：

- 根限定完整提交身份、父对象列表、分页 History 数据和最多 200 个挂载行的虚拟列表；
- 最多 100 个显式有序目标的 reviewed Cherry-pick，以及冲突进度、Continue/Skip/Abort 和重启恢复；
- 当前分支 first-parent base 到 `HEAD`、最多 1,000 个提交的 bounded Squash 和精确旧 `HEAD` lease；
- 单提交首父 Diff、提交文件树和共享文本/图片 Diff 展示边界。

本草稿初审时列出的以下缺口，已由 CM4 的范围选择与范围动作检查点补齐：

- History 范围选择、锚点/活动端点、键盘扩展、虚拟列表选区投影和 H1/H2 菜单切换；
- 对选择对象执行同根、直接 first-parent 链、完整区间、merge commit 和当前分支可达性分析的类型化预检；
- 从范围选择生成精确 Cherry-pick 顺序并预填现有计划；
- 多提交 Revert 的计划、执行顺序、进度、Continue/Skip/Abort 和协议；
- 验证显式选区恰好对应现有 bounded Squash 的 base-to-`HEAD` 完整范围。

CM4 双提交比较底层检查点又补齐了：

- 独立的 `{ repositoryId, beforeOid, afterOid }` 比较身份，以及任意两个精确提交树之间的净文件范围；
- 只接受该范围内文件身份的 bounded 文本 Diff 和双侧图片读取；文件范围受 20,000 项和 16 MiB 输出上限约束，超限明确失败而不显示不完整结果；
- 版本化桌面协议、Tauri/演示桥接和返回值校验。

后续展示检查点也已补齐 H2 菜单、自动祖先方向、分叉锚点方向、显式交换、比较文件树、独立只读 Diff 文档身份、文本/图片读取、文件导航、展开上下文和两侧 Git Blame。交换两侧后严格保留用户方向；加载、失败和重试不会短暂回退到初始方向。至此 H2 首版没有剩余架构缺口。

### 验收草稿

1. 鼠标与键盘能够选择 2–100 个连续真实提交，普通单击恢复单选；范围不能跨折叠汇总、未加载分页或占位行。
2. 在范围内右键保持 H2 选区，在范围外右键切换为 H1；右侧详情始终属于活动端点。
3. 多选身份由有序 `repositoryId + oid` 构成，虚拟滚动、分页和 DOM 复用不会改变范围；改变查询展示顺序会清除隐藏选择。
4. 复制按可见顺序输出每行一个完整 ID，并明确它不是 Git 执行顺序。
5. 两提交比较只接受同根精确对象，祖先关系或显式两侧方向正确，且不混入 `HEAD`、索引或工作区。
6. Cherry-pick 只接受顶层仓库中无缺口、非 merge 的线性链，按最旧到最新显示并执行；不会根据日期或当前行序猜顺序。
7. Revert 只接受当前分支 first-parent 上的无缺口非 merge 区间，按最新到最旧执行，并在冲突后正确显示目标进度和 Continue/Skip/Abort。
8. Squash 只接受以精确 `HEAD` 结束的完整 first-parent 后缀，后端发现隐藏提交、merge commit、缺口、无 base 或旧 `HEAD` 变化时拒绝。
9. 跨 Git 根、嵌套根、分叉图、日期排序、筛选后伪相邻和超过上限的场景均得到明确结果，不能扩大顶层仓库写授权。
10. Drop、Reset、Push、New Branch/Tag、父子导航和多页面外部打开不会以无效占位进入 H2 菜单。
11. 英文、中文、长主题、范围两端焦点、屏幕边缘、菜单关闭焦点恢复和跨越旧 3,000 条边界的 History 会话通过交互检查。
12. 实现后补充 History 列表/选择控制器、拓扑预检、Cherry-pick/Revert/Squash、双提交 Diff、桌面协议、冲突恢复、真实分叉/merge/多根仓库和安装平台接受证据。

### 后续产品与实施问题

- H2 是否只支持连续范围，还是最终需要 `Ctrl/Cmd` 不连续选择；后者必须同时设计显式执行顺序编辑器。
- “比较两个提交”形成的多文件范围 Diff 采用共享只读范围 Diff 应用服务，并供 Branches、H1/H3 与未来 Patch 预览按精确来源复用。
- 多提交 Revert 采用一次 reviewed sequencer 计划，显示完整执行顺序和进度，不拆成多个互不关联的确认。
- Squash 按首版条件保留在 H2，同时继续复用同一个 Git Operations 审查，不建立 H2 专属执行路径。
- 多选状态完整归 History 功能所有；菜单宿主只接收一次性范围身份与动作快照，不理解或维护选择生命周期。

## 草稿 H3：提交详情中的变更文件夹

### 目标与身份说明

提交详情文件树中的文件夹菜单服务于“查看这次提交在某个路径范围内改了什么，以及从该历史路径继续导航”。首版保持只读，不把历史路径集合直接变成批量工作区写入或局部历史改写入口。

这里的文件夹不是从该提交完整目录树读取的真实仓库文件夹。当前界面先读取所选提交相对第一父提交发生变化的文件列表，再按 `CommitFileChange.path` 投影出临时目录节点。它只代表“这次提交中位于该路径下的已列出变更”，不证明当时或现在目录下只有这些文件，也不包含没有变化的文件。

本草稿覆盖 Tree 模式中的非根目录节点。仓库根行只是整个变更文件列表的容器，右键不显示 H3 业务菜单；Flat 模式没有文件夹节点。提交详情中的单个文件行由 H4 单独定义。

### 打开和目标规则

- 鼠标右键命中目录 `<summary>` 时打开菜单，但不同时切换它的展开状态、不选择第一个后代文件，也不改变当前编辑器 Diff。键盘焦点位于目录行时，`Shift+F10` 或系统菜单键打开相同菜单。
- 右键只建立独立上下文高亮；提交详情中的当前文件选择保持不变，直到用户明确打开文件夹变更并在其中选择某个文件。
- 目标身份包含工作区世代、`repositoryId`、所选完整 commit OID、完整 first-parent OID 或空树身份、仓库相对目录路径，以及完整 `CommitDetails` 中属于该目录的后代 `CommitFileChange` 身份。不能只保存目录名称、展开节点或 DOM 子元素。
- 文件夹即使处于折叠状态，也从完整已加载的 `CommitDetails.files` 计算后代；不能把当前挂载的子节点误认为完整范围。详情仍在加载、失败或无法证明文件列表完整时不显示菜单。
- 切换提交、仓库根、详情请求、Tree/Flat 模式或工作区时关闭菜单。目录投影在重新读取后消失，或提交对象/第一父对象与捕获身份不符时，旧动作失败关闭而不是重定向到同名目录。
- 重命名/复制记录按当前 `path` 投影目录。移入目录的文件会出现在目标目录范围内，移出目录的记录可能只在其新路径目录下出现；`originalPath` 始终随文件身份保留并在 Diff 中显示，前端不自行补造第二棵“旧目录树”。

### 动作行为

#### 显示此文件夹的变更

- 比较边界与当前提交详情一致：普通及 merge commit 使用 Git 报告的第一父提交作为 Before，root commit 使用空树，所选提交作为 After。
- 范围是 `path === directory` 或以 `directory/` 开头的全部已列出后代变更；匹配必须按 Git 仓库路径段完成，不能用不区分大小写的界面字符串前缀。
- 打开一个有界多文件 Diff 会话：侧边列表保留状态、当前路径和 `originalPath`，用户选择一个文件后才按需读取文本或图片 Diff。Asterlyn 不把整棵目录的补丁拼成一个可能超限的编辑器文档。
- 会话绑定 `{ repositoryId, parentOid|emptyTree, commitOid, directoryPath, descendant identities }`，沿用单文件 Diff 的 4 MiB 文本截断、图片格式/像素上限、取消和过期响应拒绝。目录文件清单超过未来会话预算时必须分页或拒绝，不得静默遗漏后仍声称是完整文件夹 Diff。
- 该动作只读，不改变提交、当前工作区、Files 选择或 History 查询；关闭会话后焦点回到仍存在的目录行。

#### 在 Files 中定位

- 通过 `repositoryId` 对应根描述符把仓库相对目录映射为工作区相对路径，再使用当前 Files 目录身份重新授权；不能从字符串拼接后直接操作系统路径。
- 当前目录存在并已进入 Files 投影时，打开 Files 工具、展开祖先并选中目录，但不自动打开所有后代文件，也不改变提交详情的选择。
- 历史目录在当前工作区已删除、变成文件、位于截断目录之外、仅能通过符号链接到达或不在授权目录投影时不可用，并说明仍可查看历史 Diff 或复制路径。
- 定位只针对当前工作区。它不宣称 Files 展示的是所选提交时刻的目录内容；历史仓库浏览属于后续独立只读能力。

#### 文件夹历史（截至此提交）

- 激活后把 History 查询切换为一个根限定起点 `{ repositoryId, startCommitOid, directoryPath }`，从该精确提交向其祖先遍历并应用字面路径过滤；不会包含所选提交之后的新历史。
- 为避免当前临时筛选造成误解，该入口清除 Branch、User、Date 和其他临时 Path 条件，再安装所选提交起点与唯一目录路径；收藏、最近路径及展示偏好不被删除。
- 后端重新验证提交对象和安全仓库相对路径，并使用显式 `--` 分隔路径。历史目录无需在当前 Files 目录中存在，不能用当前工作区目录授权作为读取旧 Git 对象的前提。
- 第一版不使用 `--follow`，也不跨目录重命名追踪；投影路径只表示该提交时看到的当前路径。界面需明确“截至该提交”和“不跨目录重命名”的范围。
- 该查询会替换当前 History 结果和提交选择，因此菜单关闭后焦点进入新的 History 列表；没有匹配时显示真实空结果，不退回所有历史。

#### 复制路径

- “文件夹名”复制路径最后一个段；“相对路径”复制包含嵌套 Git 根前缀的工作区根相对路径；“绝对路径”复制当前工作区根映射出的平台原生路径。
- 历史文件夹当前可以不存在。相对/绝对路径表示它在当前工作区命名空间中的对应位置，不宣称磁盘存在，也不从所选提交导出文件。
- 值从根限定目录身份生成，不从可折叠标签、面包屑或本地化仓库显示名拼接。成功提示区分三种复制结果，剪贴板失败时显示可恢复错误。
- 二级菜单继承 Files 草稿的左右键、Escape、焦点恢复、边缘避让和指针容错规则。

### 后续候选与明确不支持

- **提交文件夹与当前工作区比较。** 必须明确提交树一侧和磁盘一侧，决定是否包含未跟踪文件与未保存编辑器内容，并进行目录存在性、符号链接、大小和文件数量预检；不能使用含混的“Compare with Local”。
- **历史仓库树浏览。** 从 commit tree 懒加载完整目录和文件，使用只读文档身份并限制对象/目录大小；不能把投影变更文件夹当成完整版本，也不能在 Files 中伪造可保存文件。
- **Get from Revision。** 若未来提供，应命名为“从此提交恢复文件夹…”，先展示会创建、覆盖、删除和保留的完整路径集，阻止脏缓冲区和未跟踪冲突，并使用可恢复工作区事务；首版不提供。
- **Patch 导出和多 Diff 标签。** 分别等待统一 Patch 模型和编辑器组/持久只读标签生命周期，不由 H3 单独实现临时版本。
- **Show Changes to Parents。** merge commit 以后可提供父提交子菜单，显示父序号、短 ID 和主题，并让多文件 Diff 明确切换 Before；不默认把所有父提交合并成一个基准。
- **不支持目录级 Revert、Cherry-pick、Extract 或 Drop。** 用户可以对完整提交使用 H1/H2 的 reviewed 操作；路径级历史修改若以后确有需求，必须单独设计完整补丁范围、提交结果、索引保持、冲突和恢复，不能复用目录展示节点直接执行。

### 当前能力与新增依赖

当前项目已有：

- 根限定提交详情、第一父提交或空树比较，以及带 `path`、`originalPath` 和状态的完整变更文件列表；
- 从变更路径投影、目录优先排序的 Commit 文件树，目录展开状态和后代计数；
- 根限定单文件提交 Diff、文本/图片展示、过期读取拒绝和 History 路径查询；
- Files 的工作区根、嵌套 Git 根映射、路径选择与展开能力。
- 根限定的精确提交 History 起点；后端验证完整对象 ID，并把它与 refs 互斥后使用字面路径查询祖先历史。

CM4 H3 检查点已经补齐：

- Tree 模式非根目录的鼠标/键盘菜单、独立上下文高亮、稳定目录范围身份和关闭焦点恢复；
- 绑定提交、第一父/空树边界和完整目录后代清单的只读多文件 Diff 会话，文件切换不会越出目录范围；
- 从历史目录身份重新授权并定位当前 Files 目录的应用动作；
- 文件夹名、工作区相对路径和绝对路径三类文本剪贴板动作；
- 从完整提交对象开始、按字面目录路径限制的 History 查询，以及替换查询后的列表焦点。

仍属后续范围的是历史仓库树浏览、历史目录与工作区比较、目录 Patch 导出和受监督目录恢复。

### 验收草稿

1. 右键和键盘在同一非根目录得到相同菜单，且不切换展开状态、文件选择或当前 Diff；根容器和 Flat 模式不出现 H3 菜单。
2. 菜单身份绑定 `repositoryId + commitOid + parentOid/emptyTree + directoryPath + descendant FileChange identities`，不能被同名目录、详情切换或 DOM 重建重定向。
3. 折叠目录使用完整详情数据计算后代；重命名/复制路径、已删除文件和嵌套目录均进入正确范围，不根据挂载节点漏项。
4. 文件夹 Diff 对普通、merge 和 root commit 使用正确第一父/空树边界，按需读取文件且对数量、文本和图片限制给出诚实结果。
5. Files 定位只在当前授权目录存在时成功，不把历史版本冒充当前目录，也不跟随符号链接越出工作区。
6. 文件夹历史严格从所选提交向祖先查询正确 Git 根和字面路径，不包含后续提交，并明确不跨目录重命名。
7. 文件夹名、工作区相对路径和绝对路径复制结果正确；当前路径不存在时不虚假宣称磁盘文件夹存在。
8. Revert、Cherry-pick、Extract、Drop 和 Get from Revision 不会以占位或未经审查的批量写入进入首版菜单。
9. 英文、中文、长路径、深层目录、根提交、merge commit、目录移动、详情加载失败、菜单边缘和焦点恢复通过交互检查。
10. CM4 H3 已补充 Commit 文件树/详情控制器、多文件 Diff、精确起点 History、Files 定位、协议、浏览器及本地构建证据；真实重命名/merge/嵌套根仓库和安装平台矩阵继续作为发布级证据。

### 后续产品与实施问题

- H3 多文件 Diff 与 H2 双提交比较、Branches 分支比较和未来 Patch 预览共享一个精确来源的只读范围 Diff 应用服务。
- 提交详情的功能绑定拥有文件夹上下文高亮，并向菜单宿主提供一次性不可变目录范围快照；宿主不保存 `CommitDetails` 状态。
- “文件夹历史（截至此提交）”是否需要一个明显的“返回之前查询”入口，而不是依赖用户重新设置所有筛选。
- 历史目录与当前工作区比较、完整仓库树浏览、Patch 和“从此提交恢复文件夹”的后续优先顺序。
- 仓库根变更容器是否最终需要一个极简菜单；本草稿先不为等同整个提交的范围重复 H1 动作。

## 草稿 H4：提交详情中的变更文件

### 目标与版本定义

单个变更文件的右键菜单服务于三个连续问题：这次提交对文件改了什么、该历史版本与当前工作区有什么不同，以及是否要把这个精确历史版本恢复到当前文件。首版以读取为主，只保留一个范围清楚、先预览且可恢复的工作区写入动作。

本草稿覆盖提交详情 Tree 和 Flat 模式中的单个 `CommitFileChange` 文件行，不覆盖 H3 的投影文件夹、Files 当前文件、Changes 工作区变更文件或编辑器标签。

下列动作共用“该行代表的历史文件版本”：

- Added、Modified、Renamed 和 Copied 使用所选提交树中的 After 文件，路径为当前 `path`；
- Deleted 使用第一父提交树中的 Before 文件，优先使用 `originalPath`，否则使用 `path`；
- root commit 不可能提供合法的 Deleted Before 版本；对象或路径关系无法验证时，依赖历史内容的动作不可用，不猜测替代对象；
- Renamed 的 `originalPath` 继续用于变更 Diff 和路径历史边界，但打开、比较和恢复的目标是提交后的新路径；Copied 不自动继承源文件的全部历史。

“显示此文件的变更”和历史文件打开属于一组；其后各分组使用分隔线。“复制路径”是唯一二级菜单。恢复项不能以普通菜单点击直接写盘：点击只进入专用预览与确认流程。

### 打开和目标规则

- 鼠标右键命中文件行时建立独立上下文高亮并打开菜单，但不同时加载 Diff、打开文件或改变当前详情文件选择。键盘焦点位于文件行时，`Shift+F10` 或系统菜单键打开相同菜单。
- 菜单目标包含工作区世代、`repositoryId`、完整 commit OID、第一父 OID 或空树身份，以及捕获时的完整 `{ path, originalPath, status }`。历史内容动作还要在后端解析并锁定 blob OID、Git tree entry 类型和文件模式；不能依赖行号、短 ID、显示文本或 DOM 元素。
- 切换提交、Git 根、详情请求、工作区或 Tree/Flat 模式时关闭菜单。文件状态、提交/父对象或工作区映射变化会使旧动作失败，不重定向到同名文件。
- 右键菜单只有在完整详情加载成功且该行身份可验证时显示。执行时重新验证安全仓库相对路径、Git 根、对象类型和读取预算。
- 历史路径可以在当前工作区不存在，所以历史 Diff、打开历史版本、History 和复制路径不以当前文件存在为前提；“与当前文件比较”“打开当前文件”和恢复动作各自执行额外的当前目标检查。

### 动作行为

#### 显示此文件的变更

- 行为与当前普通单击文件行一致：普通及 merge commit 使用第一父提交作为 Before，root commit 使用空树，所选提交作为 After。
- Renamed/Copied 同时把 `path` 和 `originalPath` 作为 Git 路径参数交给后端，不能由前端把重命名拆成一个删除和一个新增；Deleted 保留提交前内容作为 Before。
- 打开现有可替换的 `commit-diff` 预览并更新详情文件选择。沿用文本 4 MiB 限制、图片格式/尺寸限制、取消、二进制说明和过期响应拒绝；不因来自右键就创建第二套 Diff 生命周期。

#### 打开历史文件

- 后端按“该行代表的历史文件版本”解析精确 tree entry 和 blob，并以 `{ repositoryId, commitOrParentOid, blobOid, path }` 建立只读文档身份。标题和状态区域显示短提交 ID、路径及“只读历史版本”，避免与当前工作区标签混淆。
- 文本文档按统一解码和大小限制打开；受支持图片沿用图片预览边界；目录、子模块 entry、符号链接以及不支持或超限的二进制对象显示类型化说明，不伪装成可编辑文本。
- 历史文档没有保存、自动保存、格式化或覆盖当前文件的能力。要写入工作区必须显式选择恢复动作并重新进入预览。

#### 与当前文件比较…

- Before 是该行代表的精确历史版本，After 是映射后的当前工作区路径。当前文件不存在、变成目录/链接、越出授权根或超出读取预算时保持可聚焦但不可用，并显示具体原因。
- 如果对应普通编辑器标签有未保存内容，After 使用该内存缓冲区并明显标注“当前文件（未保存）”；否则按精确磁盘版本读取。动作不能为了比较而自动保存或丢弃缓冲区。
- Renamed/Copied 默认比较提交后新 `path` 与当前同一路径；Deleted 则比较提交前旧文件与当前是否重新出现的同一路径。首版不自动搜索可能再次重命名到其他路径的当前文件。
- 打开比较前记录缓冲区版本或磁盘文件修订；读取完成后状态发生变化时标为过期并允许重新加载，不能把两次不同时间的内容拼成一次可信比较。

#### 打开当前文件

- 通过 `repositoryId` 根描述符把当前 `path` 映射为工作区身份，重新授权后在普通编辑器中打开，并在 Files 中选择该文件；不先写入、不切换 Git 分支。
- 文件已经删除、变为目录/链接、位于被截断的 Files 投影之外或无法映射时不可用。用户仍可打开历史版本或查看提交 Diff。

#### 从此提交恢复文件…

- 该动作的语义是“让当前工作区目标路径获得该行代表的精确历史文件内容和明确支持的普通文件模式”。它只修改工作区，不暂存、不创建提交、不移动分支引用，也不调用会隐式影响索引的 `git checkout`/`restore`。
- 点击后先读取并固定源 `{ commit/treeish OID, blob OID, path, mode }`，再固定目标为“当前不存在”或一个精确工作区修订。预览显示将创建还是覆盖、历史来源、字节/文本或图片差异、文件模式变化、当前 Git 状态和恢复记录范围；无差异时报告无效果而不写入。
- 当前目标有未保存编辑器缓冲区时阻止执行，并引导用户先保存或取消；绝不静默丢弃内存内容。目标是目录、符号链接、子模块 entry、硬链接风险、受保护路径、超出既有恢复预算或当前有互斥写入时同样拒绝。
- 用户确认后复用受授权的工作区原子写入和持久恢复记录。写入前再次核对源对象、目标存在性/修订和工作区世代；任一变化都使计划过期并要求重新预览。失败时按事务边界回滚或提供现有恢复入口。
- 成功后刷新 Files、Changes、相关 Diff 和打开标签；结果只是普通未暂存工作区变化。即使文件属于嵌套 Git 根，也不能借此扩大 Stage、Commit、Branch 或其他 Git 写操作的顶层仓库授权。

#### 文件历史（截至此提交）

- 激活后安装 `{ repositoryId, startCommitOid, path }` 的根限定 History 查询，从精确所选提交向祖先遍历，不包含该提交之后的记录。入口清除会造成范围误解的临时 Branch、User、Date 和其他 Path 筛选。
- 对 Renamed 行，查询边界同时携带 `path` 与该次提交记录的 `originalPath`，界面明确显示这一次已知改名；首版不依赖含混的全程 `--follow`，也不猜测更早的多次改名。Copied 从新路径开始，不把源文件历史自动算作副本历史。
- 历史文件当前可以不存在；后端只要求安全的仓库相对路径和仍存在的提交对象。没有结果时显示真实空结果，不退回全仓库历史。

#### 复制路径

- “文件名”复制当前 `path` 的最后一个段；“相对路径”复制包含嵌套 Git 根前缀的工作区根相对路径；“绝对路径”复制当前工作区映射出的平台原生路径。
- Deleted 或历史中已改名的文件当前可以不存在。路径表示历史文件在当前工作区命名空间中的对应位置，不宣称磁盘对象存在，也不导出文件内容。
- 所有值从根限定文件身份生成，不从标签文本拼接。二级菜单与 F1/H3 使用相同键盘、边缘避让、剪贴板错误和焦点恢复规则。

### 后续候选与明确不支持

- **新标签中的 Diff。** 等编辑器组和持久只读文档生命周期统一后，再决定是否同时支持“新标签”与固定预览；首版复用现有单个 commit Diff 预览。
- **单文件 Patch 导出。** 等待统一 Patch 模型，明确文本/二进制、重命名、文件模式、输出上限、保存位置和许可；不从前端可见 Diff 文本拼补丁。
- **merge commit 的父提交选择。** 未来“显示相对于 ›”子菜单可列出父序号、短 ID 和主题；首版详情、文件 Diff 和菜单都保持第一父语义。
- **完整历史仓库树浏览。** “打开该提交中的文件”只打开一个已知变更路径，不等同于在该 revision 下浏览完整仓库；完整浏览器继续作为独立能力。
- **不支持文件级 Revert、Cherry-pick、Extract 或 Drop。** 完整提交使用 H1/H2 reviewed 操作；单文件需要时使用明确的工作区恢复，不把局部补丁称作 Git 历史操作。未来若增加路径级补丁应用或历史编辑，必须独立设计三方合并、索引保持、结果提交、冲突和 Abort。

### 当前能力与新增依赖

当前项目已有：

- 根限定提交详情与单文件 first-parent/root Diff，包含 `path`、`originalPath`、状态、文本/图片边界和过期响应拒绝；
- 单个可替换 `commit-diff` 预览，以及普通工作区文本/图片标签和未保存缓冲区身份；
- 工作区文件的精确修订、受授权原子替换，以及 Git 工作区写入的持久恢复记录与重整入口；
- 根限定路径 History、Files 路径映射和嵌套 Git 根读能力；
- H4 底层检查点提供精确提交文件版本读取：重新验证完整 `CommitFileChange`，Deleted 固定第一父版本，其余固定提交后版本，并锁定 treeish、blob、模式、源路径和有界文本/图片内容。
- H4 检视检查点提供独立只读历史文件文档及历史版本与当前文件比较控制器；磁盘比较固定工作区修订，未保存文本比较同时固定磁盘基线、编辑版本和完整缓冲区内容，文本/图片结果沿用有界原生展示链路。
- H4 恢复检查点提供产品中立的单文件计划、原始/恢复 blob 持久化、原子创建或覆盖、精确目标修订 lease、保守回滚和显式完成；恢复不会修改索引、引用或提交。
- H4 完整菜单由提交详情功能拥有目标、策略和动作路由，共享窗口宿主仅展示；菜单接入现有提交 Diff、只读历史文档、当前文件比较、当前文件打开和精确起点 History，并由独立恢复控制器管理审查、执行和重启恢复。

多次重命名和嵌套 Git 根的长期使用样本；它们不由菜单层另建替代能力。

### 验收草稿

1. Tree/Flat 模式的同一文件行通过鼠标和键盘得到相同菜单；右键只建立上下文高亮，不自动打开 Diff 或改变当前文件选择。
2. 菜单身份绑定正确 Git 根、完整提交/父对象和 `{ path, originalPath, status }`，对象、详情或工作区变化后旧动作不能落到同名文件。
3. Added、Modified、Deleted、Renamed、Copied、root commit 和 merge commit 都解析到正确的历史版本；Deleted 使用提交前版本，merge 首版始终使用第一父。
4. “显示变更”复用现有有界 Diff；“打开历史文件”保持只读，不能保存或伪装为当前工作区文件。
5. 与当前文件比较会区分磁盘版本和未保存缓冲区，缺失、类型变化、读取超限和中途修订变化均给出诚实结果。
6. 恢复必须先预览和确认，绑定精确源 blob 与目标修订，阻止脏缓冲区和不支持的 entry；成功只产生未暂存工作区变化并有持久恢复入口。
7. 打开当前文件和三类路径复制使用根描述符映射；历史路径不存在时不会虚假宣称当前文件存在。
8. 文件历史从所选提交开始，不包含后续记录；本次重命名边界与 Copied 语义不会被 `--follow` 猜测覆盖。
9. Revert、Cherry-pick、Extract、Drop、Patch、新 Diff 标签和父提交切换不会以无效占位进入首版菜单。
10. 文本、图片、二进制、超限对象、文件模式变化、中文/长路径、嵌套根、详情切换、菜单边缘与焦点恢复通过交互检查。
11. CM4 H4 已补充 Commit 文件详情提供者、blob 读取、只读历史文档、当前文件比较、恢复事务、精确起点 History、协议、浏览器与本地构建证据；真实 rename/delete/merge/嵌套根仓库的安装平台矩阵继续作为发布级证据。

### 后续产品与实施问题

- “打开该提交中的文件”应复用一个可替换历史预览，还是成为可固定的持久只读标签；这应与 Diff 新标签和完整历史仓库浏览一起决定。
- 历史版本与当前文件比较和 H3 文件夹比较、H2 双提交比较、Branches 比较共享统一的精确比较来源模型。
- 单文件恢复由应用服务组合历史 Git blob 读取与 R5 `WorkspaceMutationCoordinator`，复用工作区原子写入和持久恢复，不复用普通编辑器保存 UI，也不进入会修改索引的 Git Restore 计划。
- 嵌套 Git 根中的历史恢复按普通工作区文件写入授权处理：目标必须是当前工作区内可写身份，结果可以使嵌套根变脏，但不能扩大任何 Git 引用、索引或操作授权。
- 恢复成功后只执行权威刷新和明确通知，并提供“在 Changes 中查看”入口；不自动切换工具或抢走当前焦点。
