# LSP 管理插件与上游语言服务改造计划

日期：2026-11-06。状态：**用户已授权实施及分步本地提交；F0 核心契约与基线已落地，F1 推荐交互已进入本机验收收口，F2 已完成原生配方与任务注册表、桌面空目录所有权、宿主派生 authority 的 review/确认/取消协议、有界后台执行与终态事件、跨进程内容/索引事务、受限 HTTP/TLS 下载、受控解包及不可变发布/卸载恢复基础，具体服务端与版本尚未选定。** 逐步契约与验证见 [基础实施记录](2026-11-06-lsp-foundation-contract.md)。

架构决定：[ADR-0038](../architecture/decisions/0038-managed-upstream-language-servers.md)。本计划取代此前讨论的“分别发布 TS/JS、Rust、Android JVM 语言插件”建议，延续现有语言服务、插件、项目模型与资源治理。

## 1. 用户确认的目标与本次范围

- 保留 `dev.asterlyn.lsp` 插件和独立仓库，使其成为开启 LSP、提供服务目录、管理安装/卸载、与宿主通信的统一入口。
- 插件启用后，用户在编辑区打开受支持类型的文件，底部状态栏推荐缺失的对应 LSP；推荐本身不下载、安装或执行。已安装且项目/精确授权有效的服务可沿宿主既有生命周期按需启动，无需每次重复安装或批准。
- 用户明确安装后，由宿主完成受控安装；服务启动继续经过项目执行授权。插件关闭时不推荐、不自动启动，基础编辑与 Git 正常工作。
- 采用官方或开源 LSP 发布制品，停止扩大自维护语言引擎、编译器分叉和复杂语义桥接的范围；保留必要的协议、项目配置和运行环境适配。
- 先完成基础，再迁移现有 Rust、TypeScript/JavaScript、Android Java/Kotlin。TSX/JSX 及原有模块后缀属于现有覆盖；Groovy、Gradle DSL、Kotlin 脚本和几十种新语言不预先宣称支持。
- 先核实语言官方团队的 LSP；缺少可用官方实现时，在 GitHub 优先检索 Rust 实现。候选交用户决定，未决定的后端不进入默认推荐/安装目录。实现语言偏好不替代能力、许可、维护和资源验证。
- 最初落档阶段仅修改文档。后续用户已授权产品实施与分步本地提交；远端推送/发布不包含在本次授权中。具体上游选择仍由用户决定。

## 3. 目标职责与两类安装

| 所有者 | 负责 | 边界 |
| --- | --- | --- |
| LSP 管理插件 | 语言/服务目录、推荐规则、安装卸载意图、语言配置与必要适配 | 经已准入的命名能力通信；无直接网络、文件系统、shell 或进程句柄 |
| 宿主通用语言服务 | 目录准入、下载校验、安装状态/事务、执行审查、文档同步、会话、取消、恢复、资源与 UI | 每项事实只有一个权威拥有者；Tauri 保持平台/传输适配层 |
| 上游 LSP | 解析、类型、补全、导航/引用、诊断及其原生语义能力 | 使用已批准 profile；实际 capabilities 决定可用功能 |
| Android Gradle 插件 | 已有任务/运行与项目模型服务 | 仅具体需要模型的配置建立依赖，与全局管理开关解耦 |

“安装管理插件”继续沿用插件市场、不可变包、健康检查、重启和回滚；“安装上游服务”是独立的受管工具事务，具有独立版本、运行时、安装记录、使用租约和会话生命周期。各语言服务不必分别成为 Asterlyn 插件，不要求增加多个发布仓库，现有每个 Release 一个插件包的规则继续有效。

目录由轻量管理插件提供，服务端资产按需安装。目录声明和管理请求属于待设计契约，不能假定现有 SDK 已支持。优先复用现有可选组件安装、存储及监督设施，避免复制安装或会话状态。

## 4. 声明模型与协议基础

F0 冻结最小版本化模型，具体字段、协议版本和数值上限在实施评审中确定：

| 模型 | 必须表达 |
| --- | --- |
| 语言选择器 | 稳定语言 ID、普通/复合后缀、必要的精确文件名、项目条件、优先级/冲突规则；复用权威识别结果，避免另一张硬编码后缀表 |
| 服务目录项 | 稳定 server ID、覆盖语言、官方/社区归属、上游仓库、支持平台、已验证功能/项目范围、安装配方与兼容条件 |
| 安装配方 | 精确版本、平台制品、可信来源/摘要、许可/通知、发布入口、体积、运行时、受限启动方式和可选模型要求；无任意可执行安装脚本 |
| 安装事实 | 未安装/安装中/已安装/失败、不可变版本/摘要、受管目录、运行时、当前/回退选择与使用租约 |
| 运行事实 | 缺少运行时/未授权/启动中/分析中/就绪/部分可用/恢复中/停止/失败；绑定窗口、项目、服务、包、配置及文档版本 |
| 项目偏好 | 选择的提供者、是否启用、推荐抑制；不能作为安装成功或执行授权的证据 |

安装状态与运行状态分开，安装完成不等于语义就绪。一个服务可以覆盖多种语言；初期每个语言/项目选择一个主语义提供者，重叠时显式选择，不自动双开。未来 lint/formatter 组合留扩展点，首期不做多服务结果仲裁。

通用启动 profile 按已验证方式扩展，例如原生 stdio、固定 Node 入口、受控 JVM 入口。插件声明静态要求，宿主校验真实工具、固定参数、工作目录及最小环境；不能把通用化做成任意 command/shell 执行。仅为运行方式或必要兼容差异增加适配，不在宿主不断增加语言业务分支。

目录、管理请求、错误、结果和事件须同步覆盖 SDK、原生权威模型、类型生成、运行时验证与漂移检查。旧宿主拒绝未知必需能力；字段退化、枚举、safe integer、资源上限和固定错误类别一起冻结。SDK、管理协议、安装持久 schema、目录和上游版本分别治理，计划阶段不提前统一升版。

## 5. 打开文件后的推荐与管理交互

1. 仅在插件启用、当前窗口拥有有效项目、用户打开/激活可编辑源码后，以语言身份和项目条件查询本地目录/安装快照。历史 Diff、只读依赖预览、图片、未知类型不推荐安装；识别 `.kts` 不代表其语义已验收。
2. 缺少已经选定并准入目录的服务时，底部栏显示如“Rust 语言服务未安装”，提供“安装”“查看”“本项目不再提示”。选型未决定/兼容性未知时说明待配置或不支持，不推荐未经决定的候选。
3. 点击安装展示来源、版本、下载量、运行时和安装范围，确认后创建宿主管理任务。安装与项目执行是不同授权；未信任项目可进行只读推荐，但不能触发项目脚本或语义启动。
4. 底部栏显示下载/校验/安装进度和取消，失败说明原因并允许显式重试。已安装但缺运行时、未批准或项目不匹配时给准确动作，不重复推荐安装。
5. 安装成功后，仅对仍有效项目走正常执行审查；精确授权可复用，身份变化重新审查。切文件/切项目后的旧结果只能更新正确安装事实，不能抢回旧文档或启动旧项目。
6. 管理入口列出当前支持语言、已安装服务/版本/来源/运行状态，以及安装、卸载、启动/停止、重试和推荐设置。复用已有语言状态与诊断入口，避免重复界面。

推荐按项目/服务去重，临时关闭与项目持久抑制区分并可恢复。快速切标签、多语言共用服务和多窗口不能重复下载或弹出。推荐路径不联网检查最新版、不执行 GitHub 搜索、不扫描全部项目、不启动全量索引；已安装服务的实际分析仍由有效授权和生命周期管理。推荐查询有界，重型管理视图按需加载。

控件支持键盘、无障碍名称、明确终态反馈和编辑器焦点恢复。新增动作同步登记到[快捷键清单](../architecture/keyboard-shortcut-coverage.md)，快捷键与按钮共用安装/卸载审查路径。

## 6. 安装、卸载与资源治理

- 下载到应用私有 staging，校验来源/重定向、平台/架构、版本、摘要、许可和安全解包后，原子发布到不可变版本目录并提交唯一安装索引。失败/取消保留旧选择，支持中断恢复与幂等清理。
- 使用上游正式发布制品，不从已安装 IDE 提取源码、JAR、字体或其他资产。核验上游签名/发布摘要、GitHub asset digest 或包管理器 integrity；首次下载后计算的本地 hash 不能冒充独立来源证明。来源无法核验时记录为候选阻碍，不静默绕过规则。
- 使用受管二进制或私有 package prefix，不修改用户项目、全局 npm/工具链、Gradle 缓存和 shell 配置。确需 npm 等分发时固定依赖闭包/integrity，默认禁止安装生命周期脚本；需要构建的候选另定受控方案，不运行任意 shell 安装器或 `curl | sh`。
- 已安装外部工具可作为显式选择，检查真实路径、版本和内容身份；卸载仅删除受管制品，不删除用户自行安装的 Node、JDK、Rustup 或 LSP。
- 运行时与服务分开管理；缺少 JDK、Node、rust-src 时显示前置条件。检查上游隐含下载和执行行为，不能因默认行为静默安装运行时、Cargo 依赖或项目包，也不能扩大现有 build-script/proc-macro 执行范围。
- 卸载使用中的服务先展示受影响窗口/项目，确认后停止对应会话、撤回诊断、取消请求并释放租约，再事务化取消选择和回收制品；保留编辑器脏缓冲区。其他窗口仍使用的版本不能提前删除；历史清理保护活动/回退版本。
- 禁用/卸载管理插件撤销其贡献并停止所拥有会话/任务。服务端文件清理是独立明确操作；保留资源可从宿主插件资源入口检查/清理，不能成为无入口残留。
- 同一制品下载可以合并，安装提交/取消边界明确。安装/更新语言服务通常只重启受影响会话；管理插件升级仍遵循现有插件重启机制。
- 复用统一内存准入、进程监督、有限恢复、结果代际及缓存边界。同窗口/项目复用兼容会话，跨窗口共享不可变制品和安全派生缓存，未保存文档隔离。安装/启用插件不等于启动语义进程；压力/闲置释放策略经实测冻结，不为低占用无限重启或盲目压低堆造成 OOM。
- 分别报告 JVM 堆上限、整个进程树 RSS/物理 footprint、磁盘缓存及下载体积。独立进程/插件隔离不代表原生 LSP 已被 OS 沙箱限制。

## 7. 上游来源与用户选型

下表仅为 **2026-11-06 的资料核查**，不是已测试、已选定或已安装的清单。实施时固定真实发布版本、许可、制品摘要和启动参数；旧 README、编辑器扩展或宣传不证明独立运行和 Android 兼容。

| 当前语言 | 官方优先核查 | 当前证据及待决事项 |
| --- | --- | --- |
| Rust | [rust-lang/rust-analyzer](https://github.com/rust-lang/rust-analyzer)、[安装说明](https://rust-analyzer.github.io/book/installation.html) | Rust 官方组织实现；确认受管二进制/现有工具来源、toolchain/rust-src 兼容和默认下载/执行行为 |
| TS/JS | [microsoft/TypeScript](https://github.com/microsoft/TypeScript)、[旧 typescript-go README](https://github.com/microsoft/typescript-go/blob/main/README.md) | 旧库已归档，旧 README 将 LSP 标为开发中并说明合并方向，主库当前可见 Go 源码；可安装 LSP 的实际发布入口、命令、TSX/JSX/JS 成熟度待核实，不能套用旧 `tsserver.js` 布局 |
| Java | [Oracle Java Platform](https://github.com/oracle/javavscode)、[Eclipse JDT LS](https://github.com/eclipse-jdtls/eclipse.jdt.ls) | 优先核查 Oracle 官方供应路径；该页面描述编辑器扩展，独立服务分发待验证。Eclipse 是其自身项目的官方实现，不等同 Oracle/Java 语言官方；Android 变体与混合 Kotlin 能力分别实测 |
| Kotlin | [JetBrains Kotlin LSP](https://github.com/Kotlin/kotlin-lsp)、[语言官方文档](https://kotlinlang.org/docs/kotlin-lsp.html) | 官方来源明确；当前上游说明含 Alpha、实验性 Android 支持及部分闭源组件，需核实实际二进制分发许可、JVM/平台要求和真实项目能力，不能仅据仓库 LICENSE 推断可再分发 |

现有 [typescript-language-server](https://github.com/typescript-language-server/typescript-language-server) 明确标为非官方；调用 TypeScript 引擎不改变该身份。OpenIDEA 使用的 vtsls 也不能因此视为语言官方。它们仅供基线/候选对照，不自动成为新默认项。

流程：核实官方及独立分发 → 缺少可用官方时记录原因、优先检索 GitHub Rust 实现 → 提交候选对比 → 用户决定 → 固定版本/许可/完整性 → 实际探针 → 准入目录。不得为实现语言偏好维护新的不完整引擎。

候选对比记录：官方归属/实现语言、维护/发布状态、许可证与完整分发条款、平台/架构、运行时、下载/磁盘体积、同项目冷/热耗时和进程树内存、实际功能/未保存支持、Java/Kotlin 互操作、Android/Gradle/变体范围、更新/回滚路径。未知数据明确标记，不能用 Python 或不同内存口径推断 JVM 场景。

## 9. 兼容迁移与验收门禁

- 保持 `dev.asterlyn.lsp` 身份/来源，区分管理插件、目录、服务、运行时与协议版本；SDK 复用精确 canonical 制品，历史包字节不变。
- 选择/推荐设置显式映射到新 server ID；历史批准不能复制为新引擎执行授权。旧包资源在被运行/回退使用时受保护，不自动清理用户历史包/组件。
- 未安装新引擎时显示明确的旧模式/迁移状态，同项目显式择一。旧依赖/新服务不兼容时保留基础编辑并说明原因，不伪装就绪。
- 旧包提供符号候选规则，退役前明确规则新归属和缓存迁移；保留既有符号入口与“语法候选”标识，不把它升级为精确语义。
- 通用测试覆盖 SDK/目录准入、协议漂移、选择器冲突、安装/恢复、授权撤销、多窗口、离线已安装使用、受限环境与完整退出。下载/删除测试使用可丢弃夹具，不操作用户真实制品。
- 语言测试覆盖当前实际支持的定义/引用/补全/诊断等能力，以及错误源码、UTF-16/non-BMP、CRLF/BOM、快改、过期结果、切项目、EOF 和包/工具变化。WorkspaceEdit、重构或任意 executeCommand 不因上游支持而自动开放。
- 性能按同机器、项目/变体、功能和工具版本测量；冷/热各至少 3 次、代表导航至少 30 次，分别记录窗口可用/服务启动/真实语义就绪、p50/p95、宿主及整个后端资源与退出残留。基础空闲与主动语义工作分别给预算，F0 冻结门槛，不预设 Rust/官方一定更省。
- 相应区域变更执行 `npm run check`、`npm run test:scripts`、`npm run build`、相关 Rust 测试/Clippy、插件独立 verify/准入、真实 stdio 与渲染门禁；Git 区域未变不额外扩大无关测试。各平台实际执行分别记录，macOS 不代表 Windows/Linux 已通过。
- 产品实施后的本机交付遵循 [local-build.md](local-build.md)：精确插件/服务健康检查、完整签名/严格验证、canonical Contents-only 安装、摘要一致与两次图标书签重开。仅本次文档落档不触发该流程。
