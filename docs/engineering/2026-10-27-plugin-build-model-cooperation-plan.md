# 插件构建模型协作与强依赖实施计划

日期：2026-10-27。用户已批准先落档、再实施、分步提交；本计划修订前一轮 Android/JVM 职责划分。

## 已确认的产品规则

`dev.asterlyn.lsp` 启用期间，所依赖的 `dev.asterlyn.android-gradle` 必须保持启用。这是插件级强依赖，
适用于 LSP 整体的启用状态，包括 TS/JS/Rust，不能自行缩窄成“仅打开 Android 文件时锁定”。
启用不等于激活或启动进程：依赖插件可以已启用但在非 Gradle 项目不匹配，且不运行模型任务。

- 启用 LSP 时，原生端检查依赖闭包的安装身份和兼容版本。已经安装的兼容依赖可在同一事务中启用；
  缺失/不兼容时明确拒绝并提供修复入口，不隐式下载或略过依赖。
- 已启用的直接或间接依赖者存在时，拒绝关闭/卸载依赖，以及会破坏依赖版本约束的切换/回滚。
  设置页显示依赖者和原因；原生管理入口再次校验，不能只禁用 UI。
- 用户先关闭 LSP，依赖锁立即解除；Android 插件保持自己的启用选择，不随 LSP 自动关闭。
  其他已启用依赖者仍存在时继续锁定。
- 依赖者崩溃、索引空闲、工作区不匹配不解除“已启用”依赖；运行故障不会把启用偏好偷偷改掉。
  缺失/隔离的依赖使依赖者不可执行，并清理所属工作；不会通过依赖启用绕过执行授权。
- 全局安装启用关系由原生端维护；所有窗口收到变更后重投影，依赖判断不只看当前窗口激活列表。
  循环、自依赖、重复声明、超限、未知字段和非法版本必须拒绝。

## 责任与边界

| 组件 | 所有权 |
| --- | --- |
| 宿主/SDK | 通用依赖图、包准入、受控附属程序、异步工作、取消/回收、有界制品缓存与引用、文档/编辑器安全边界 |
| Android Gradle 插件 | Gradle/AGP 版本适配、模块/变体、source sets、编译依赖、Android boot classpath、已有生成源码、模型 schema/失效规则 |
| LSP 插件 | 服务器和插件资源、模型消费、后端专用适配、语言配置及诊断一致性；按需启动 |

Android 业务不继续堆到宿主。附属进程仍由宿主准入、启动和回收，算法和版本适配随所属插件交付。
当前隔离 JS 插件没有文件/进程 API，不在其回调锁中直接跑 Gradle/JVM，也不通过长期 callback 返回大模型。

## 协议与生命周期

1. 在 manifest/SDK 增加通用、有界、版本化的强依赖声明和宿主 capability。旧包不声明则保持原行为；
   旧宿主不能把新强依赖包当作可独立启用的包。每条依赖包含插件 ID 和明确版本区间。
2. 引入模型提供/消费契约；服务 ID、schema 版本、生产者身份、工作区/构建根、输入指纹、选择意图、
   模型 generation/digest 组成身份。宿主掌握执行/访问范围；Android 字段契约由插件拥有。
3. 大模型存受控制品，回调只传引用、状态、版本和计数；消费需校验当前身份/范围。模型中的路径不能自行
   授予文件读取或可执行权限。失效、禁用、替换、取消使旧引用和结果不可被继续采纳。
4. 模型缓存与 Gradle Tasks 缓存分别管理；共享一致的构建输入监测和选择意图，不把任务名推导当完整模型。
   Run 的应用变体由模型确认，并解析依赖模块实际变体，而不是将同一名称套到所有模块。
5. 首个消费者需要时启动模型工作，任务相同则合并；只有轻量 Tasks/Run 时不启动 LSP 和语义导入。
   不默认构建 APK/运行处理器，网络和额外生成任务有独立执行意图。
6. 各后端实际消费模型分别证明；没有统一 JSON 所有服务器天然可用的假设。Kotlin 发行和混合 dirty overlays
   闸门仍保留，不因依赖关系实现就宣称 Android 语言服务可用。

## 验收及资源

- 强依赖测试用至少三节点传递关系和两个依赖者，关闭一个依赖者后不能提前解锁；图算法有节点/边上限。
- 安装/升级/回滚与启用变更使用同一权威图检查；并发变更不能留下启用消费者但依赖已被关闭的状态。
- UI 有可见原因、可访问描述和键盘操作；依赖锁区别于“正在操作”。失败不展示虚假的已保存状态。
- 通用内核不引入 AGP/JDT/Kotlin 二进制；未使用语言功能时不启动 JVM。记录包大小、冷/热耗时、根进程/整树
  内存样本及范围，协议上限不等同真实内存预算。
- 原生日志保留固定原因、身份摘要、计数和耗时，不持久化源码、完整模型/classpath、环境或仓库凭据。

### C2 拆分与当前边界

C2a 先交付无文件/进程/框架依赖的模型任务内核：原生权威快照校验、共享任务和租约、代次及精确制品引用、有界状态、失效/取消/超时。
C2b 再接受监督的附属程序和磁盘制品；C2c 才公开 SDK/包声明及提供/消费调用。不得把 C2a 的元数据核称为完整模型通道，也不提前授予插件读写文件或任意执行权限。

C3a 已用独立 AGP V2 探针在 boostCleaner 的 :common/cleanx100Debug 取到真实模型（8 个源码目录、1 个 boot classpath、56 个存在的编译依赖、0 未解析），5.1 秒左右；探针和规范化 schema 归 Android 插件。
探针是开发工具，尚未打入生产包；依赖模块图、生成源码、取消过程整树回收和 C4 后端消费仍未验收。

本轮已完成 C1 的原生交付；C2a 与 C3a 作为可复核基础分步提交。最终包、安装和剩余闸门见 [本轮交付证据](../benchmarks/2026-10-27-plugin-cooperation-delivery.md)。C2b/C2c/C3 完整模型/C4 均未标记完成。
