# LSP 命令、行为与资源基线

日期：2026-11-06。本步为 F0.6，延续[基础实施记录](2026-11-06-lsp-foundation-contract.md)与[安装状态契约](2026-11-06-lsp-installation-state-contract.md)。它冻结迁移前事实和后续命令边界，不选择上游、不新增 SDK 权限、不开放安装路由。

## 现有用户命令

现有命令继续属于“项目语言会话”，不能复用于安装管理：

| 命令 | 当前行为 | 新架构中的归属 |
| --- | --- | --- |
| `languageServices.status` | 打开当前项目的提供者、进度、资源与失败状态 | 保留；只展示运行事实，可从管理入口跳转 |
| `languageServices.retry` | 停止并重建当前项目会话 | 保留；不下载、修复或切换服务版本 |
| `languageServices.debug.enable` / `.disable` | 当前应用会话内切换元数据调试记录 | 保留；不记录源码或原始协议，不持久化 |
| `languageServices.forgetProjectConsent` | 清除当前项目执行批准并停止会话 | 保留；不卸载制品、不删除偏好或缓存 |

当前原生执行接口为 `language_service_workspace_state`、`set_language_service_resources`、`set_language_service_debug`、`prepare_language_service`、`start_language_service`、`forget_language_service_consent`、文档 open/change/close、request/cancel 和 stop。它们只处理已存在的旧 profile；`prepare` 是执行审查，不是安装审查。旧接口在迁移完成前保持兼容，但不得接受任意 URL、路径、命令或启动参数。

## 新管理命令边界

下列名称是产品/应用层命令 inventory，不是本步已经存在的 IPC 或插件 API。F2 只有在原生持久存储、真实校验器、权限准入与协议生成同时完成后才能逐项开放。

| 应用命令 | 输入事实 | 允许结果 | 明确不做 |
| --- | --- | --- | --- |
| `managedLanguageServers.refresh` | 当前宿主安装索引 | 重新读取并复验受管/外部制品 | 联网查版本、启动服务 |
| `managedLanguageServers.show` | 当前项目和可选服务身份 | 打开宿主管理视图 | 改变选择或批准 |
| `managedLanguageServers.install` | 已准入精确配方、target、当前 index revision | 打开宿主审查，确认后创建安装任务 | 插件自批、任意 URL/脚本、自动启动项目 |
| `managedLanguageServers.cancel` | 当前任务的原生句柄 | 请求取消并保留旧选择 | 用客户端 ID 取消其他窗口任务 |
| `managedLanguageServers.retry` | 已结束任务和仍准入的同一配方 | 重新审查后创建新任务 | 重放旧批准或复用旧临时目录 |
| `managedLanguageServers.remove` | 当前受管制品、使用窗口/项目清单 | 审查后等待租约并事务移除 | 删除外部工具、回退版本或用户运行时 |
| `managedLanguageServers.select` | 已安装且复验通过的制品 | 审查后更新 current/rollback | 获得项目执行批准、静默选择历史制品 |
| `managedLanguageServers.verify` | 已有精确制品身份 | 复验真实存储，更新瞬时 verification | 修复、重装或把索引 JSON 当作证明 |

底部栏动作与命令面板必须调用同一应用命令。插件未来只提交静态配方身份和管理意图；插件 callback 不能充当确认按钮。安装审查绑定窗口激活代际、插件版本/包摘要、配方与 index revision；项目执行仍走独立的 `prepare_language_service` / `start_language_service` 审查。

## 迁移前行为矩阵

| 场景 | 当前实现 | 迁移期要求 | 完成后的目标 |
| --- | --- | --- | --- |
| 插件禁用 | 撤销贡献并停止所拥有会话 | 取消该插件未完成的管理任务；实际进程租约继续到 owner 释放 | 不再推荐；已安装文件保留，明确清理 |
| 打开支持文件但无服务 | 没有通用推荐；旧贡献不存在即无语义能力 | 只有目录、平台、项目和安装事实均为当前值时显示 | 底部栏给已选服务的精确安装动作 |
| 服务已安装但重启后未复验 | 旧 profile 直接从插件包布局解析 | 新路径不得显示 ready 或启动 | 显示待校验，复验后才可获得使用租约 |
| 安装/更新失败 | 不适用 | 保留 current/rollback，终态错误可查看 | 显式重试；不重复提示“未安装” |
| 多窗口同时需要同一服务 | 旧会话按窗口/项目建立 | 安装任务按服务合并，使用租约按真实会话持有 | 只下载一次；最后租约释放后才可删除 |
| 当前版本卸载 | 旧插件包卸载与语言资源耦合 | 先阻止新租约、列出影响、停止对应会话 | 原子取消选择并移除受管制品 |
| 外部工具 | 旧路径会探测标准位置的 Node/Rust | 显式选择和精确身份；不得冒充受管安装 | 可复验/使用，不提供删除动作 |
| 项目切换/快速切标签 | 运行客户端已有 workspace/document 代际 | 安装事实请求也必须有本地请求身份和宿主 epoch | 旧结果只能更新对应全局任务，不能抢回 UI/启动旧项目 |
| 无网络 | 已安装旧 profile 可运行 | 推荐路径不联网；缺失服务只展示已知配方 | 已复验安装继续可用，下载明确失败且保留旧版本 |
| 只读/历史/依赖预览 | 不建立可编辑文档语言绑定 | 不显示安装推荐 | 可查看已有语义来源，不触发安装或执行 |

现有 `LANGUAGES` 后缀表、贡献声明与新目录在迁移期并存。F1 的推荐只使用已准入目录；现有会话继续按旧贡献匹配，直到每种语言完成真实上游验收。不得把目录识别结果直接喂给旧执行 profile，也不得因旧 profile 可运行就伪造新安装事实。

## 资源与性能门槛

当前通用资源池是软准入而非 OS 沙箱：全局分析预算为物理内存一半并限制在 1,536–24,576 MiB；自动单服务上限为 `min(4,096 MiB, budget - 512 MiB)`；用户可选 1,024/2,048/4,096/6,144/8,192 MiB，但必须至少留下 512 MiB；队列最多 64 项，等待最多 120 秒，进程组 RSS 每 2 秒抽样。新受管服务必须进入同一池，不能再建一套互不知情的内存计数。

上游候选验收必须分别记录：下载/展开/安装磁盘量；空闲及主动语义时整个后端进程树 RSS；冷/热到真实语义就绪；至少 30 次代表查询的 p50/p95；停止后残留进程。原生、Node、JVM 用同一口径。旧 P0 数据只作迁移对照：TS 观测峰值 595 MiB、JS 717 MiB、Rust 1,400 MiB，Android JVM 1,905–2,083 MiB；这些是特定样本的后代 RSS，不是新后端预算或桌面物理 footprint。

首批候选的最低门槛：不能超过宿主资源池准入；空闲 10 分钟不得出现无界增长；主动停止后 5 秒内受监督进程组为零；推荐/安装状态本身不得启动后端。若新候选在同项目/功能口径下明显高于旧基线，必须把差异、能力收益和可调上限交给用户决定，不能以实现语言推断更省内存。Java/Kotlin 的 JVM 堆上限、进程树 RSS和共享/独立进程策略分别报告。

## F0.6 验收边界

本步通过源码与既有回执建立基线，不重跑耗时的真实 Android/JVM 项目。现有 2026-11-03 五场景基线含 30 次启动、每启动 30 次代表查询、结果摘要一致与退出后零残留；它对应旧服务组合，后续每个新上游必须重新测量。命令 inventory、失败/恢复/迁移矩阵和资源口径已冻结；具体安装 IPC、安装 UI、target 探测和新上游数值仍由 F1/F2 及语言阶段验收。

本基线提交于 `6902f2c`。

## F1.1 活动目录与底部栏展示基础

宿主插件管理快照现在投影已准入的 `languageServerCatalog`，但推荐层只接收当前项目中同时 `enabled && active` 的目录；设置页可见、已安装但未激活、匹配但激活失败、已禁用的插件不会贡献推荐候选。投影提交于 `7930b9b`，相关 24 项测试和类型检查通过。

应用 shell 增加默认空的 `managed-language-status-host`。功能层提供纯状态映射和 HTML：不合格文档/未知语言/已安装时保持空；未配置、平台不支持、提供者冲突、安装事实不可用、待校验、可恢复、可安装、安装/卸载进度各自有明确状态。安装事实读取失败只有管理入口，不显示安装动作；进度使用原生任务的有界字节值并提供可访问名称。中英文文案、转义、live status、busy/progress 语义和可聚焦按钮均有测试。

这一步没有把展示组件绑定到应用状态，也没有给按钮注册回调：当前 host 为空，因此产品界面不会出现无效动作。F1 后续必须先接入当前原生 target、活动插件目录、项目文件证据和安装事实读取，再绑定宿主管理命令；安装路由完成前仍不显示安装按钮。真实 Chromium/WebKit 的切文件、焦点恢复、键盘与减少动画验收尚未完成，不能由字符串测试替代。

最终类型检查、生产构建和全量 1,603 项脚本测试通过。第一次全量脚本检查仅因 `shell.css` 达到 833 行触发样式所有权门禁；状态样式迁回语言功能目录、登记唯一入口后，门禁与全集通过。没有网络、文件扫描、进程启动、SDK 变更、插件改动或本机应用替换。
