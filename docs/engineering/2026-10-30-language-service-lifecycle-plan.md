# 项目语言服务启动、进度与调试链路

- 日期：2026-10-30。用户要求恢复 Android 索引工作，交付持久授权、自动索引、可见进度和仅调试时生效的操作追踪。
- 基线：宿主 `5a61449`，LSP 插件 0.3.7，Android Gradle 插件 0.6.2。延续分阶段文档、实施、验证和本地交付。
- 业务职责保持在插件：宿主管理通用授权、进程、模型引用、状态与编辑器；Gradle 插件提取项目模型；LSP 插件适配 Java/Kotlin 后端。

## 已有证据

会话 `session-1793327919440-28041-0` 中，`language-session-28041-2` 在启动后约 5.6 秒记录
`model.failed(code=model-unavailable)` 和 `workspace.degraded(code=language-request-rejected)`。
之后的导航仍收到 indexing，直到会话终止；同一问题在第二个会话重现。模型 worker 的 error
记录没有原因分类；普通 indexing 请求还被计入 `backend.failed`，不能据此判断后端真正崩溃。
现有前端授权 Map 只保留窗口/项目会话，原生 review 只使用一次且 60 秒过期；不持久保存同意。

## 阶段与完成标准

### L0 文档与基线

先提交本计划及插件侧计划。保留原始失败日志；每个阶段记录类型/单测、真实协议与原生证据。
不修改业务项目源码、凭证或系统 TLS 配置，不把失败变成空的成功结果。

### L1 持久授权

原生持久保存项目批准，使用规范工作区身份绑定 profile、插件包/资源链及实际工具身份。
不绑定窗口、一次性 review ID、激活世代或模型缓存位置。不同 worktree、目录替换、插件/依赖插件
或工具变更都重新审查。每次启动仍重新校验活动工作区、启用状态、包和工具，消费新的短期 review。
损坏、版本不支持或超限的授权存储不能当作同意；采用有界、串行和原子更新。
弹窗明确告知“为此项目记住”，暂不启用只影响本次项目会话；提供清除此项目授权的入口。

### L2 项目启动与状态

项目和已匹配 provider 就绪后，对声明需要项目模型的 provider 自动启动一次，不等待打开 .kt/.java。
使用已验证的原生声明识别候选，不在宿主增加 Gradle/Android 文件识别。首次仍需授权，此后匹配批准
即可自动索引。预热与文档打开共享一个会话；普通刷新和任务刷新不重复启动。窗口/项目切换、关闭
或插件停用及时取消；旧回调不能覆盖新项目。终止后的状态可重试，不能永久粘在 failed 会话上。

### L3 真实进度与失败

状态栏持续显示模型准备、源码准备、后端启动、索引、就绪、降级/失败。详情提供经过校验的阶段、
真实计数、用时、原因和重试；没有可靠总量时使用不定进度，不伪造百分比。正常 indexing 不记录为
backend failure。插件报告真实转换；宿主仅校验、关联 session 并展示通用阶段。
模型失败和后端停止必须结束“索引中”，普通悬停不反复弹 toast；仍保留明确可见的失败与诊断。

### L4 调试追踪与根因定位

显式开启当前应用会话的语言服务调试追踪，默认关闭、退出复位；支持调试入口与探针环境开关。
记录项目/provider 协调、授权请求/复用/失效、模型调用/阶段/失败分类、进程/会话终止原因、打开/
修改/关闭文档、导航/悬停/补全/引用请求、版本、取消/丢弃、耗时、结果数及有限的后端事件。
用 trace/request/session/workspace/document 标识关联，文档用哈希，源码只记版本和字节数；不记录
源码、符号、补全内容、诊断原文、原始 RPC、凭证、构建命令或完整环境。遵守现有 JSONL 队列、
轮转、脱敏及限流；关闭时不产生详细操作事件，正常健康/失败摘要继续保留。
Gradle worker 的失败只输出安全原因分类和异常类型链，不回传任意 stderr 或项目配置内容。

### L5 集成与交付

按新日志复现 FilesRecovery 的模型失败并修复可验证根因，再回归 boostCleaner。验收包含项目重开/
应用重启不重复批准、无需开文件自动启动、失败/重试/项目切换、Kotlin/Java 实际导航及调试开关。
缺少网络、依赖或项目条件时准确报告，不假称完整索引就绪。保持 TS/JS、Rust 与基本编辑可用。
记录功能、阶段耗时/资源样本、状态/监听器边界、键盘/可访问性及明确限制。完成宿主测试、插件
测试/完整包检查、签名、原生 smoke、规范覆盖安装和图标重开。只本地分步提交，不推送或发布。

## L2–L4 实施与阶段验收（2026-10-30）

- 原生发现已安装包声明的模型型 profile，前端仅在对应贡献已启用时预热；后台会话与编辑器共用一个传输，关闭最后一个文件继续索引，切换项目/关闭插件即撤销。
- 首次启用记录原生项目授权；刷新 review 仍须一次性、有效项目范围及相同插件/工具身份。等待授权超过有效期可重新准备相同身份，不重复弹确认；工具变化或已撤销授权拒绝重用。
- 独立页脚入口显示真实阶段、模块/文件完成数与本轮耗时；失败停止转圈，可重试和清除项目授权。部分 Kotlin 模块尚未就绪时 Java 继续服务。视图在宿主重绘后重新挂载，销毁时清理计时器和监听。
- 应用会话调试默认关闭，可通过页脚详情/命令面板开启，或显式以 `ASTERLYN_LSP_TRACE=1` 启动调试。跨窗口同步开关，退出应用后恢复关闭；默认不设置系统环境或持久化开关。
- 记录文档打开/变更/关闭、导航手势/目标选择、请求完成/取消/过期丢弃、模型与后端阶段、终止和资源限制原因。日志含窗口、会话、项目/文档 hash、版本、计数及耗时；无源码、符号、原始 RPC、原始 stderr 或凭证。原生及前端均有 120/s 追踪上限。
- 普通索引等待属于正常状态，不再刷 `command.failed`；真实导入失败保持安全错误类别。模型工作器的异常类型链/脚本 basename+行号仅调试时附加，单行输出有界，分片 stderr 不丢失错误末记录。
- FilesRecovery 确认并修复生产者凭证空覆盖根因，约 15 秒导入 6 模块；无运行配置时由实际 AGP 模型确定默认变体，明确失效选择保持失败。
- 阶段验证：宿主脚本 1364 项（以最终结果为准）、原生库 177 项通过/2 项系统监听、1 项公网 Release 集成检查默认忽略；模型分析层 10 项集成检查及安全进度单测通过；Gradle 74 项、LSP 13 项通过。状态面板 Chromium/WebKit 覆盖进度/失败/重试/调试开关/焦点/减少动画/重绘与资源清理。

- 最终原生安装、重复启动授权复用与 boostCleaner 验证结果另行补记；当前记录不替代完整交付验收。
