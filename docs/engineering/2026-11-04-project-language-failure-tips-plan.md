# Actionable project language-service failure tips

Date: 2026-11-04. Plan recorded before implementation.

## Incident and intended behavior

The FilesRecovery worktree at `launcher-module-rebuild` cannot import its selected Android model because `:feature-push` lacks the cached JAR for `org.jetbrains.kotlinx:kotlinx-coroutines-play-services:1.10.2`. Independent execution of the installed 0.6.4 model worker reproduced `incomplete model dependencies`. Existing terminal records lose this detail as `model-unavailable`; successful task discovery does not resolve compile dependencies.

Clearly classified project failures must produce an error tip in the host's existing bottom-right notification center, including the affected module/dependency when available and a recovery instruction. The service status view retains the same information after dismissal. Ordinary users do not need debug tracing to see actionable failure information.

## Boundaries and stages

1. The Android Gradle model producer classifies unresolved compile dependencies before normalization. It emits a bounded structured project-failure record containing a fixed reason, validated module and Maven coordinate, and omitted-count information. Never transmit raw Gradle exceptions, repository URLs, credentials, source text or arbitrary executable messages. Keep dependency downloads and project edits explicit; no automatic dependency installation is introduced.
2. The generic native analysis boundary revalidates the record. Model access associates it with the exact model-load attempt; the language actor attaches it to the current session's failure and clears it after successful model replacement. The existing native serde contract generates the additive frontend failure type. No Android import logic enters the host.
3. The frontend formats localized actionable messages and publishes error notifications only for confirmed project failures in the current workspace/provider scope. Deduplicate repeated failed events within one failure episode; ready/retry/new workspace permits a later notification. Keep cancellation, deliberate stop and temporary indexing silent. The same formatter supplies the status view.
4. Focused worker/native/session/frontend tests cover missing offline dependencies, other fixed project causes, malformed/private metadata, stale sessions, repeated events and recovery. Run affected complete checks and production build. Package the changed immutable plugin, canonically inspect it, then create/sign/install a fresh native app using the existing installer and verify two icon restarts plus logs and the real FilesRecovery worktree tip.
