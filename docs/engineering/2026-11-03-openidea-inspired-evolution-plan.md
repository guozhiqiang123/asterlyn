# OpenIDEA 借鉴与 Asterlyn 基础能力演进计划

日期：2026-11-03。状态：**P0 分阶段实施中**。

初次落档仅制定计划；随后用户已授权先实施 P0 并分步验证、提交。其余阶段尚未实施；不升级宿主版本或发布远端。实现、自动验证、安装验收及人工验收分别记录。

## 1. 目标与参考范围

改善真实开发循环中的可用性、恢复能力、交互延迟和工程可维护性：项目打开后能理解当前分析状态，语言服务中断后能受控恢复，导航及时响应，能力增加时宿主仍保持轻量。

OpenIDEA 值得参考的是项目服务、轻量索引、语言服务生命周期、类型化协议和体验预算。功能清单不能证明 IDEA 全量语义兼容，Python 热缓存数据也不能用于推断 Android 大项目性能。此前对照是源码、调用链、测试及 CI 配置的静态审计，没有进行两款应用的同条件性能对测。

## 2. 已有能力与文档衔接

以下能力已存在，本计划补齐缺口，不重新建设：

- 项目级语言授权、自动预热、真实阶段进度及仅调试时启用的详细追踪。
- Android 模块产物缓存、保守增量失效、有限并行、跨模块 Java/Kotlin 引用及窗口私有未保存覆盖。
- Gradle 兼容 JDK 选择、运行前复验、授权和任务缓存绑定实际运行环境、分类失败日志。
- 插件调用超时、JavaScript 中断、滚动 CPU / 内存边界，以及精确包准入、健康检查、隔离、回滚、必需依赖锁。
- 版本化命令表与运行时校验、文本搜索索引、统一 Find 树、引用弹窗和默认排除 import。
- Git 精确预览 / 执行令牌、受控 force-with-lease、变更恢复和结构化诊断。

本计划延续 [既有架构重构](architecture-refactoring.md)，不重开已验收阶段，也不把机械拆文件作为目标。关联计划：

- [统一 Find](2026-10-30-unified-find-results-plan.md)、[Gradle Java 修复](2026-11-03-gradle-task-java-runtime-plan.md)。

## 5. O0：基线与契约清单

固定宿主 build ID / 摘要、实际启用插件版本 / 包摘要、工具 / 组件身份、项目源码 / 变体 / 模型指纹、OS / 机器及构建模式。缓存测试使用独立命名空间，不清空用户全局 Gradle 或分析缓存。

代表场景：Asterlyn 的 TS/JS 与 Rust；boostCleaner 25 模块，以及 `GlobalConfigNew.kt` 声明查引用、`AppAds.kt` 的 `initialize` 导航和刷新 Gradle 后继续导航；FilesRecovery 用于不同体量 Android 回归；私有夹具覆盖 Java/Kotlin 双向引用、同名符号、非法依赖、脏缓冲区、后端退出、授权撤销和模型替换。

测量要求：

- 冷 / 热启动各至少 3 次，区分窗口可用、当前模块可用与完整分析就绪，不能用 CPU 下降代替语义就绪。
- 固定导航至少 30 次热查询，报告首查、p50 / p95、各阶段及结果渲染耗时；比对规范化 URI、精确范围和覆盖状态，不能只比数量。
- 采样宿主、helper、Node、JDT / Kotlin / Gradle 和 WebView 辅助进程；标明 RSS / PSS / phys_footprint / private bytes，不能直接跨口径比较。
- 故障清单覆盖未批准、工具缺失、提供者冲突、分析中、过期结果、模型失效、意外退出、协议失败、资源上限、隔离和主动停止。

O0 产出可复现的验收矩阵、调用链 / 所有权图及初始预算。实际实施文件清单经 CodeGraph 影响分析后冻结，不按候选目录机械搬迁。

## 6. O1：结果完整性与提供者选择

保留现有启动 / 索引进度，补齐恢复、部分可用及失败状态。状态来自实际监督、后端能力和模块范围，不能由单一全局 ready 布尔值替代。

契约分别表达数量受限与分析覆盖范围：结果、文档 / 会话 / 模型身份、覆盖状态（完整 / 部分 / 未知）及固定原因（分析中、候选过多、文件跳过、后端不可用等）。字段与版本协商在 O0 冻结；旧包未报告时视为未知，不推定完整。弹窗和 Find 共用原始结果与覆盖元数据；排除 import、路径筛选及树 / 平铺只改变投影，不改写覆盖事实，也不合并过期结果。

提供者按项目、语言及功能选择：显式项目选择优先，其次唯一且能力 / 兼容性满足要求的默认项；仍冲突时显示候选，不静默空绑定。改变选择须撤销旧绑定并校验新身份 / 授权。只有明确声明且获授权的备用项才可回退；空结果不构成切换理由，也不能用文本匹配替代语义结果。

验收：零 / 一 / 多候选，禁用或卸载当前项，项目切换，分功能能力，旧包无新字段，全量 / 部分 / 零结果，弹窗 → Find 后覆盖与筛选一致。新增入口同步命令与快捷键清单。

## 7. O2：有限恢复与故障闭环

宿主监督打包适配进程，LSP 插件监督内部 JDT / Kotlin。相同进程只有一个恢复所有者，内部恢复与整个适配器重建不能竞争。

仅对已分类的临时启动故障 / 意外退出自动恢复。主动停止、项目离开、撤销授权、工具 / 包身份变化、隔离、协议违规和资源上限不进入自动循环。模型变化重新获取有效模型，不复用失效租约；写操作绝不随语言恢复重放。

建议初值：最多 3 次自动重启，退避 500 ms / 1 s / 2 s，连续健康 180 s 后重置计数；O0/O2 测量后冻结参数。按实际 profile 处理索引 / 初始化时限，不能由短查询超时误杀正常冷分析。

恢复使用新会话代际，旧请求结束为取消 / 过期，重新同步仍打开文档的最新未保存文本。关闭 / 删除的文档不复活，旧诊断撤回，重复事件不重复导航；恢复可用性不代表自动补做用户已离开的点击。沿用有效精确批准，身份改变走正常审查。

验收包括启动即崩溃、运行后退出、持续失败后停止，恢复期间编辑 / 关文件 / 切项目 / 撤销授权 / 换模型，两个窗口不同脏内容、不同内部后端分别失败和完整退出回收。用真实进程夹具验证，不只测状态枚举。日志关联原因、重试次数、代际、模型重取与文档同步数量，不输出正文。

## 8. O3：工具链身份上下文

基于现有 Java 发现与 Gradle 运行身份，定义通用快照：角色、来源、版本、规范化位置 / 内容身份、要求、选择依据、可用性与固定失败类别。构建 JVM、源码目标版本和语言服务器 JVM 是不同角色；插件声明项目兼容规则，宿主负责验证、授权和作用域受限环境。

Java 先试点，Node / Rust / ADB 按实际需求接入。选择与变化在产品内可解释，并关联模型 / 缓存失效和授权复验。保留显式配置优先级，不悄悄覆盖不兼容选择，不全量继承 shell 环境，不自动下载工具，不复制 IDE 安装目录内容。

验收图标 / 终端启动、空 / 不兼容环境、显式选择、同版本不同安装、工具替换、不同 JVM 角色、跨平台路径、缓存复用 / 失效，以及 boostCleaner 任务扫描。

## 9. O4：体验与跨平台验证

聚焦测试随实现完成。逐步把核心 Rust / 协议 / 监督夹具纳入 macOS、Windows、Linux 矩阵；平台专用、公网和桌面依赖测试分别标记，不以静默 skip 代替验证。轻量检查进入常规 CI，大型 Android 探针使用专用验收任务，不默认扫描私人目录、清缓存或联网恢复依赖。

| 指标 | 初始目标，O0 校准后冻结 |
| --- | --- |
| 显式导航反馈 | 100 ms 内可见；等待反馈不等于结果完成 |
| 已就绪项目固定代表位置首查 | 目标 ≤ 1 s，不能以重复缓存命中代替首查 |
| 当前快照重复语义查询 | 至少 30 样本，目标 p95 ≤ 500 ms；结果集合 / 覆盖状态一致 |
| 后端结果到首个结果帧 | 目标 ≤ 50 ms，按结果规模分别测量 |
| 冷 / 热分析就绪 | 先记录分阶段分布，再冻结项目预算，不承诺未测时限 |
| 资源 / 泄漏 | 固定循环检查进程、监听器、DOM、内存和临时目录回收，保留现有硬上限 |

沿用 [质量门禁](quality-gates.md)、[键盘能力清单](../architecture/keyboard-shortcut-coverage.md) 与 [本地交付](local-build.md)。新增入口包含焦点恢复、键盘、失败反馈及无障碍检查。常驻成本与按需启用峰值分开记录；预算脚本存在不代表已接门禁或已通过。

## 10. O5/O6：服务与协议渐进迁移

O5 先选任务监督、语言生命周期、工作区身份等清晰责任片，补所有权测试后迁往无 Tauri 依赖的现有核心 crate 或经论证的新模块。新 crate 由依赖与失败边界决定，不以行数或数量为目标。桌面层保留原生适配，核心通过明确端口获得身份、时钟、进程和事件；每片迁移保持协议 / 行为一致，不新增双写与转发空壳。

项目重载保温限定在有效身份内；不直接跨窗口共享可变缓冲区或 JDT 目录，不为远程平台提前改造所有服务。

O6 以原生序列化模型作为数据形状权威，现有命令表保留命令 / 版本治理。先对任务或语言结果做一个生成 / 校验 / 漂移检查闭环，再选定工具；不为工具改变 wire 格式。覆盖 camelCase、枚举、nullable / optional、未知字段和 JS 安全整数，保留运行时验证。错误分离 code、可重试性与展示文案。

O1–O3 必需的新契约同步现有生成 / 验证机制，不等待全库迁移。SDK 或安装协议变化独立记录协商、最低宿主、旧包退化及包级激活证据，不在计划阶段预升全部版本。

退出标准：选定闭环不启动桌面即可测试，适配层变薄且状态所有者唯一；wire / 类型 / 运行时兼容回归通过，已有授权、Git、任务和插件治理不变。

## 11. O7：按需轻量符号索引

复用目录身份、文件事实和现有搜索缓存，不新建第二份项目文件真相。语言插件提供语法包与提取规则；宿主负责通用记录、调度、版本校验和展示。先以 TS/JS、Rust 验证闭环，再经真实 Android 模型扩展 Java/Kotlin。

持久记录只存已保存源码的派生数据，键绑定项目 / 文件身份、内容摘要、提取器 / 语法包、配置与 schema。未保存内容使用窗口私有覆盖。验证新增 / 删除 / 重命名、关闭期间变更、监听丢失、包 / 工具变化、损坏和容量淘汰。

先提供明确的符号查找与有界候选查询。语法候选标明来源，LSP 确认后才作为语义结果；Android 候选必须与合法模块依赖相交，不能按后缀或同名绕过。后台预算与交互协调，部分构建不阻塞文件查找。数据库或 Tree-sitter 引入前论证现有索引复用、依赖与包体成本。

验收首查 / 增量 / 热重开、错误候选、同名、Unicode 范围、脏内容隔离、提取器卸载及语义结果一致性。

## 12. O8–O10：后续能力门槛

**O8 Workspace Edit：**宿主提供通用事务，绑定项目 / 文档版本、文件摘要、范围、授权和一次性计划。多文件及资源操作先预览再复验；失败可恢复、整体可撤销，崩溃后能识别未完成事务。外部新修改拒绝被旧计划或旧撤销覆盖。单文档显式命令复用版本 / 撤销边界，不为格式化强制增加多文件确认。插件产生编辑方案，不直接写用户文件；闭环通过前不声明 `workspace/applyEdit`。先选一语言的一能力试点。

**O9 本地历史：**复用编辑与恢复机制，采用内容寻址、去重和私有本地快照。首版显式项目启用，先确定排除、保留期限、容量、权限、关闭 / 清理及恢复预览。本地历史不替代 Git 或恢复日志，源码不进入诊断包；多窗口和崩溃恢复独立验收。

**O10 静态贡献包：**先限定主题 / 文件类型 / 配置等无执行场景。数据包与代码包共享完整性、兼容性、卸载和回滚治理；数据包使用期间无 helper。语言配置不能借静态声明运行任意命令，工具启动仍走声明 / 审核 / 监督。旧宿主明确拒绝未知类型。WASM 仅留独立评估，不迁移现有 ABI，不归因为 JVM 性能解法。

## 13. 分步交付与退出门槛

后续获实施指令后，每阶段按可独立构建的责任片交付：契约 / 拥有者文档 → 实现与必要回归 → 精确产物、资源 / 性能 / 无障碍 / 故障回执。改变既有架构决定时先补 ADR；按后续授权分步提交，不混入多个阶段的半成品。

失败时可关闭新可选能力或重建已验证的派生缓存；不盲目重放写操作，不修改安装状态伪造健康。保留现有调用、输出、CPU、内存和并发边界。

产品修复通过必要检查后，按仓库要求新构建、完整签名 / 严格验签、标准安装器覆盖、精确摘要及两次图标书签重开。文档落档不触发构建安装。源码检查、包级验证、原生健康和人工验收分别记录，不能相互替代。

每阶段回执包含提交 / 包 / 工具身份、项目与变体、结果集合 / 覆盖状态、耗时分布、资源口径、恢复与取消、日志事件关联、平台、限制和人工验收状态。详细调试默认关闭，标准健康 / 故障摘要保留；不记录源码、符号、凭证、完整环境或原始 RPC / stderr。
