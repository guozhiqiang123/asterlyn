# Terminal T1 acceptance evidence

Date: 2026-09-14

Status: locally accepted; Windows and macOS installed-package interaction remains deferred

## Scope and contracts

T1 adds one explicitly opened terminal to each project window. Terminal is a user-draggable activity
entry and shares the resizable bottom tool region with Git History. Hiding preserves the session;
Close, project replacement, and window destruction terminate it. An ordinary folder is sufficient;
Git is not required.

The browser-facing terminal runtime and stylesheet load only after activation. The frontend owns
xterm rendering, bounded scrollback, focus, fitting, input batching, and stale-event rejection. A
product-neutral Rust crate owns the PTY, shell process, exact project working directory, bounded
input and dimensions, and process cleanup. Tauri authorizes commands against the active window and
transports only versioned, session-qualified, sequence-numbered events with base64 output bytes.

No task discovery, repository command, hyperlink activation, persistence, telemetry, output
indexing, remote shell, or automatic execution is introduced. `portable-pty` 0.9.0,
`@xterm/xterm` 6.0.0, and `@xterm/addon-fit` 0.11.0 are exact-version dependencies with MIT licenses;
their lockfile integrity and package impact were reviewed in the T1 design change.

## Resource and package evidence

The native process probe used the same release executable and an isolated desktop profile. It
recorded the complete application process tree after startup had settled, activated Terminal once,
waited two seconds, and sampled the same tree again.

| Native release sample | Before Terminal | After first activation | Normalized change | Conclusion |
| --- | ---: | ---: | ---: | --- |
| Processes | 3 | 4 | +1 shell | expected |
| Aggregate RSS | 579,244 KiB | 591,184 KiB | +11,940 KiB / +2.06% | mixed |

The additional process was `bash` at 5,220 KiB RSS. The remaining 6,720 KiB movement occurred in
the application and WebKit process while xterm mounted. This is a single native sample rather than
a repeated steady-state series, so it establishes the activation shape but does not support a
general memory-regression claim. Idle cost is structurally avoided by the lazy frontend graph and
the absence of a PTY before activation. A repeated Linux/macOS/Windows series is the next resource
action before T2.

## Remaining acceptance

Windows ConPTY and macOS installed packages still need manual interaction coverage for IME/CJK
input, full-screen programs, signals, foreground jobs, resize storms, sleep/wake, and process-tree
cleanup. Those are T3 hardening gates, not reasons to load terminal code on the idle path. T2 should
not add tabs, shell selection, or task integration until the bounded session-count and aggregate
output budgets are designed.
