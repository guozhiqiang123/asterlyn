## 修复与所有权

1. 适配器 EOF 不再永久锁死客户端；宿主先复验原批准身份，再有界重建。最多三次退避，持续健康 180 秒才重置。改变工具 / 包、撤销授权、主动停止、协议或资源错误不自动恢复，也不自动弹出新授权。
2. 重建只同步仍打开文档的最新脏缓冲区；关闭 / 切项目取消定时器。旧导航不重放，旧回复 / 诊断及引用选择弹窗由结果代际失效。内部 JVM 重启与文档同步使用不同代际，避免对仍存活的适配器重复 didOpen。
3. Android 插件拥有 JDT 与各模块 Kotlin 的恢复预算，宿主不竞争重启其内部进程。预算独立于 Kotlin 两槽 LRU，用户继续点击不能绕过；失败模块保留错误，Java 仍可用。
4. Android 原有无条件模型失败轮询已收紧，凭证 / 模型配置错误停止；显式模型失效才可重新评估。JDT 退出后旧 peer 不再被误判为可复用后端，恢复重新请求模型。
5. 无变化的模型轮询不再推进代际，避免有效后台通知在运行一段时间后被丢弃。真实故障探针曾发现这一状态竞争，修复后重验最终包。
6. JVM OOM 分类只留下固定资源错误；分类器最多保留 128 字符私有尾部，不保存 stderr 正文，不进入自动重启循环。详细恢复计数 / 代际仍仅在启用调试后记录。

## 真实 boostCleaner 故障回执

使用最终封包解压目录、真实 25 模块模型、校验工具 / 组件和独立会话缓存。所有杀进程操作只针对探针自身适配器进程组的直接 JVM 子进程，未停止用户 Gradle daemon 或其他 IDE 的 JVM。

| 场景 | 结果 |
| --- | --- |
| 初始 GlobalConfigNew 精确引用及无变化轮询 | 引用摘要一致，轮询后仍可查询 |
| JDT 子进程意外退出 | 约 49.6 秒完成重建和语义复验；模型重新获取、最新未保存内容保留 |
| 同一 Kotlin 模块第 1 / 2 / 3 次退出 | 约 9.9 / 11.3 / 11.7 秒恢复；精确引用集合一致 |
| 同一 Kotlin 模块第 4 次退出 | 停止，等待 2.5 秒后没有自行复活 |
| Kotlin 停止后 Java 查询 | HttpClient 的真实 Java hover 仍可用 |
| 源码与退出回收 | 源码摘要未变，测量进程组剩余数为零 |

这些时间包含退避、JVM 初始化与结果复验，不承诺恢复立即完成，也不是热导航耗时。脏内容只在会话内，未写回真实项目。
